## 2. 实验问题与成功条件

### 2.1 四个问题分开回答

1. **组批有没有省计算？** 比较实际计算设备秒和 `G_batch`，再看短请求被整批绑定后是否迟到。
2. **顺序和错峰有没有降低全局代价？** 固定批成员与读取字节，仅改变实例映射、领取次序或启动时刻，记录受影响的其他批。
3. **相较实用基线是否有净收益？** 对同一 trace 同时报告相对 FCFS 和 `B*` 的配对收益，计入控制开销。
4. **何时不该使用复杂调度？** 在无竞争、计算饱和、观测陈旧、过载和成本过高时公开 no-go 或回退区域。

四个优化目标 `theta ∈ {M,S,T,R}` 每次运行只选一个。M 为有限工作集 makespan；S 为失败请求数；T 为总 TTFT；R 为总归一化 TTFT。汇报 T、R 时除以固定请求数，优化与展示排序不变。

### 2.2 能力与信息两张表分别控制

主实验所有策略共用：候选批的物理可行域、实例数、字节、profile、申请协议、完整批屏障、无丢弃、无预取、同刻排序和老化保护。简单规则立即派发属于其策略选择，它们在接口上同样可以返回 WAIT；“不等待”不能被实现为不同的引擎。

证明**信息价值**时必须连候选请求、候选批、联合动作和搜索预算都固定，只替换观测来源。证明**搜索价值**时固定信息和动作集合，只替换评分或搜索深度。比较完整算法与 FCFS 的总收益可以包含选择规则差异，但不得把这个差异直接归因于某个单独机制。

## 3. 测试基线是什么，怎样对应现有框架

### 3.1 本文的“框架基线”含义

主基线 `cq_fcfs` 是 **vLLM / SGLang 到达序调度机制在本研究架构中的投影**：请求在中央队列按到达序组成可行完整批，空闲实例立即领取，命中部分统一读取。它不是启动真实 vLLM 的端到端跑分，也不是“Dynamo 默认性能”。

原因是本实验主动统一了 D1 执行时绑定、D2 中央组批、D4 按层读取和 D5 完整批执行；实际框架可能有本地等待队列、continuous batching、chunk、缓存树和多种 connector。对应关系沿用既有 D1–D7 定义，不能把这些差异藏掉。

| 策略 ID / 图例 | 确定的决策规则 | 对应工作与决策点 | 映射等级与不包含部分 |
|---|---|---|---|
| `cq_fcfs` / FCFS | `(arrival_s,rid)` 排序，连续前缀贪心填批 | vLLM / SGLang 的 FCFS，D2；命中读取对应 D4 | 机制投影；不复现 continuous batching、chunk 或 connector 全栈 |
| `cq_lpm` / LPM proxy | `(-h_tokens,arrival_s,rid)` 排序填批 | SGLang 可选 LPM，D2/D3 | 仅长命中优先代理；无 radix 树共享、淘汰和 worker locality |
| `cq_spt` / SPT | `(T0_s,arrival_s,rid)` 排序填批 | 调度论中的固定参考服务时间规则 | 强简单基线；不冒名为某框架默认 |
| `cq_edf` / EDF | `(deadline_s,arrival_s,rid)` 排序填批 | deadline-first D2 对照 | 强简单基线，不是产品默认 |
| `cq_slack` / Slack | `(deadline_s-now-pred_singleton_s,arrival_s,rid)` 排序填批 | Cascade 的预算驱动 D2 思路 | 预算机制代理；不是 Cascade 复现；没有其两层队列和完整 retrieval policy |
| `cq_pair` / Complement | 最老请求为锚，按 §7.2 互补距离排列其余成员并填批 | 原分析的读算互补启发式 | 本研究简单算法，不对应产品默认 |
| `cq_local` / Local candidate | 与 MPC 共用候选/联合动作；按 §7.4 忽略跨 worker 干扰的完成时间评分 | 控制局部与全局评价差异 | 方法对照 |
| `cq_mpc` / Global rollout | 有限候选、联合动作、终端排空，按 theta 全局评分 | 本文提出的 D1 执行时绑定 + D2 组批/准入 | 普通可观测策略 |
| `cq_current_oracle` | 同 MPC，同候选与预算；当前资源真值替代观测，未来仍恒定外推 | 信息诊断 | 不能称离线最优 |
| `cq_exact_grid` | 全目录、有限网格、全动作枚举/B&B | 小实例离线参考 | 仅对记录的网格与目录有证书 |

命名使用 `cq_` 新命名空间，不改 `default2/tensorcast2/partial_static2` 等既有 v2 策略语义。新实验不属于既有 v2 引擎，不复用其 `*2` 名称。

## 4. 物理模型：必须产生唯一轨迹

### 4.1 请求、批和 worker

请求不可变输入 `RequestSpec(rid,arrival_s,h_tokens,u_tokens,class_id,T0_s,deadline_s)`，`rid` 为从 0 开始的整数。要求 `arrival_s≥0,h≥0,u≥1,T0>0,deadline≥arrival`。E20 允许独立指定各层字节和计算目录，不反推虚构 token。

运行状态单独保存，生命周期只有 `FUTURE → QUEUED → ACTIVE → DONE`。不允许重复领取、丢弃、重算、切分、预绑定本地队列或 DONE 后重新读取。输入 singleton 不可行时，整个 scenario 校验失败；不得跳过它或暗中 chunk。

批成员使用升序 `tuple[rid,...]`，作为规范化身份。每次实际领取按 `(dispatch_s,worker_id)` 顺序生成单调 batch_id。批领取到末层计算结束期间锁住 worker，STALL 时也不能接另一个批。成员全部在末层结束时同时得到 F。

默认硬约束为 `1≤n≤8, Σu≤8192, MemPeak≤16 GB`。内存峰值按 §5.1；预算已扣模型常驻权重，不能再次扣权重。所有策略调用同一个纯函数 `is_feasible(members,limits,profile)`。

### 4.2 执行依赖与申请速率

每个实际批、每层最多一个聚合流；读取量是成员之和，不去重。层号从 0 到 L−1。

$$
V_{βℓ}=\sum_{i∈β}v_{iℓ},\quad
A_{β0}=τ_β,\quad C_{β0}=R_{β0},\quad
C_{βℓ}=\max(R_{βℓ},Z_{β,ℓ-1}),\quad Z_{βℓ}=C_{βℓ}+c_{βℓ}.
$$

若 `ℓ+1<L`，在 `Cβℓ` 提交下一层流，`Aβ,ℓ+1=Cβℓ`。首层完成读取前没有计算；末层计算开始后不提交额外流。

| 条件 | 引擎的唯一行为 |
|---|---|
| 首层 `V>0` | `q=q_max` |
| 下一层提交，`V>0,c_prev>0` | `q=min(q_max,V/c_prev)`；到期时刻为当前层实际计算结束时刻 |
| `c_prev=0,V>0` | 立即 `q=q_max` |
| `V=0` | 同刻 ready，不创建流、不消耗提交序号 |
| 到期未读完 | 提升为 `q_max`，保留原序号，不能撤回重提 |
| 读完 | 删除流并设独立 `read_ready[layer]` 标志 |

`c_prev` 在主模型使用共同的真实执行画像；这是引擎内部的统一协议，并非给 scheduler 开放资源真值。E24 只扰动调度预测，不改引擎的申请协议；若需要研究引擎对计算窗口也估错，须另建实验规格并对所有策略同时应用。

### 4.3 存储 FCFS 按申请上限分配

`B(t)` 是本业务可用总带宽，不再叠加一个未知存储队列。背景流量用可用带宽 schedule 表达，主模型不包含排队背景对象、固定 RTT 或第二跳 fabric。

按 `submit_seq` 升序依次计算：

```text
free = B(now)
for flow in active_flows_sorted:
    flow.rate = min(flow.q, max(0, free))
    free -= flow.rate
```

区段 `[t,t_next)` 内速率不变，`served=rate*(t_next-t)`。下一个时刻是读取完成、计算完成、到达、带宽断点、观测更新、控制返回或唤醒中最早者。读取完成时间由正速率流的 `remaining/rate` 算出，不用固定 dt 近似。

schedule 为右连续、从 0 开始、严格递增时间点的非负有限 `tuple[(time,value),...]`；最后一项永久延续。真实 B 可为 0；无未来恢复时返回 `undrainable`，禁止陷入无限循环。常规正式场景最后带宽为正，永久停机只作边界测试。

### 4.4 同一时刻的阶段顺序

实现显式阶段循环，不依赖 SimPy 回调注册顺序。一个 t 的处理顺序固定如下。

1. 积分到 t，结算 `[last_t,t)` 的字节与 worker 时间。处理该时刻已完成的读取、已完成的计算、请求到达、带宽变更；到达请求只进入中央队列。
2. **先推进已有活动批**。按 worker_id 升序启动依赖已满足且尚未执行的层，提交下一层读取；由零字节/零计算引发的同刻事件继续闭包，直到已有批不再有立即动作。每一轮按 `(worker_id,layer)` 排序。
3. 发布该时刻应交付的观测；处理控制器返回和统一的新批领取。联合动作先全量验证，再按 worker_id 升序领取，提交首层流；这些提交晚于步骤 2 的旧批流。同刻新领零工作批引发的闭包在其后执行，不反插到旧批前面。
4. 尚未完成的到期流提升申请率，保留序号；重新分配带宽。提升速率不会让任何字节在零时间内传完。
5. 若出现新空闲 worker 且有队列，可在同刻触发下一轮派发，但每轮必须实际领取至少一个请求；纯 WAIT 不允许以 t 为唤醒时刻。循环至固定点后推进时间。

同刻多个有字节新流的序号由“阶段 → 闭包轮次 → worker_id → layer”确定。worker 编号参与 FCFS 排位，因此精确求解不能未经证明合并交换 worker 后的状态。

### 4.5 数值、记账与终止

E20 解析、枚举和证书使用标准库 `fractions.Fraction`，十进制配置从字符串转有理数，不先转 float。生产仿真用 float64；只清理由运算误差产生的微小负剩余字节：阈值 `1e-12*max(1,original_GB)`，更大负值直接报错。有限事件比较采用统一 `1e-12 s` 归并容差，记录 `numeric_mode`；解析 SLO 边界由有理数测试覆盖，正式 SLO 成功判断用 `F<=deadline`，**不得额外放宽 SLO**。

worker 在任意区段恰属于 `COMPUTE/STALL/IDLE`。已领取、没有正在计算且未结束的批计 STALL，包括首层读取；无活动批计 IDLE，包括主动等待和控制器忙时。首轮不设置 worker OTHER；CPU 决策耗时单独记录，不能再算一次设备时间。

每批有 `F−dispatch=compute_s+stall_s`；每请求有 `TTFT=queue_wait+batch_compute+batch_stall`。请求视角的 batch_compute 会对每个成员重复出现，用于解释 TTFT；设备总量只按批求和，禁止把请求表里的计算相加当设备时间。

## 5. 画像、参考时间和输入 trace

### 5.1 synthetic-v1 的完整定义

首轮固定 `L=32,κ=4.096e-6 GB/token/layer`，令

$$
N=\sum u_i,\quad A=\sum[u_i h_i+u_i(u_i+1)/2],\quad
η(N)=\min(1,\max(1/16,N/N_{sat})),
$$
$$
c_{βℓ}=t_{launch}+aN/η(N)+bA,
\quad (N_{sat},t_{launch},a,b)=(512,50e-6,2e-7,1e-10).
$$

所有层相同；只算真实新 token 和有效 attention 配对，不按最长序列 padding。

`MemPeak=0.5+L*κ*Σ(h+u)+(16*4096*2/1e9)*N` GB。`v_iℓ=κ*h_i`，非命中后缀的 KV 计入内存但不计远端读取。h=0 的请求不创建读取流。

无合批加速对照同时设 `η≡1,t_launch=0`；这样任意批纯计算等于其 singleton 之和。只令 η=1 而保留 launch 会继续存在固定开销摊销，不能标为“无收益”。

| 类 ID | h | u | 每层 c（秒） | 总远端 GB | singleton K（秒） | B_ref=80,q_max=200 下 T⁰（秒） |
|---|---:|---:|---:|---:|---:|---:|
| HS_US | 512 | 128 | 0.0001597792 | 0.067108864 | 0.0051129344 | 0.0051391488 |
| HS_UL | 512 | 2048 | 0.0007742752 | 0.067108864 | 0.0247768064 | 0.0248030208 |
| HL_US | 8192 | 128 | 0.0002580832 | 1.073741824 | 0.0082586624 | 0.0136798560 |
| HL_UL | 8192 | 2048 | 0.0023471392 | 1.073741824 | 0.0751084544 | 0.0755278848 |

以上是公式代入校验值，不是实测性能。尤其 HL_US 的后续读不能藏完，T⁰ 不等于“首层读取+全部计算”。

### 5.2 T⁰、SLO 与负载刻度何时冻结

`T0(request)` 由独立 singleton 重放生成：空系统、B_ref=80、q_max 使用该协议组的连接上限、无背景扰动、同 profile/层数/字节，arrival=dispatch=0；不得使用当前场景拥塞带宽。恒定层画像时独立解析检查为

`T0=V_layer/min(B_ref,q_max)+L*c+(L−1)*max(0,V_layer/min(B_ref,q_max)−c)`。

默认 SLO 为 `deadline=arrival+α*T0, α∈{2,4,8}`；固定阈值对照为 `arrival+α*weighted_median(T0_class)`。类权重使用冻结的场景分布。加权分位数定义为升序累计权重首次达到 p 的值，不插值。同一对照面板不随策略、实际批或观测误差改变 T0/SLO。

每个结构组 `(profile,m,类分布,L,q_max)` 在 B_ref=80 下计算 `λ0=min(80/E[V],m/E[K_singleton])`，期望按类概率解析求和；然后冻结该组的 λ。默认组 `λ0=140.24622300091912 req/s`。扫描 B 不重算 λ0；跨 profile/m 的归一化组另记 λ0，不把不同绝对到达率的图叫同 trace 因果比较。E21 的效率因果扫描特别固定默认 λ0 和到达 trace。

### 5.3 解析及控制变量专用的合成 trace

采用 NumPy `Generator(PCG64(SeedSequence([seed,stream_id])))`，stream_id 固定：0 到达、1 请求类、2 外部环境误差、3 profile 测量噪声。禁止使用 Python `hash()` 生成种子。固定 NumPy 版本进入 manifest，实际 trace 保存后其他策略只读。

- Poisson：从 t=0 起累加 `−log1p(−U)/λ`，U 取 stream 0 的均匀数；保留 `t<duration` 的到达。
- 突发：每 20 s 的 `[0,10)` 为 1.6λ、`[10,20)` 为 0.4λ，循环；通过累计强度的逆函数逐个映射相同 Exp(1) 增量。跨阶段不能丢弃已抽的等待时间。
- 每个到达按 stream 1 的 U 映射类累计概率，类顺序固定为上表；从 0 按到达序赋 rid。同刻外部输入按 rid 打破平局。
- 默认四类各 25%；比例扫描只将 HL_US 改为 0.1/0.5/0.9，其余三类平分剩余概率。
- 带宽扰动独立预生成，所有策略共享 `((0,B),(60,0.5*B),(100,B))`。不因调度决策重采样。
- 正式 workload 以 §5.5 指定的 `mooncake_trace/` 为准；本节仅服务单元测试、四类正交机制实验及 Poisson/突发诊断，不替代真实 trace 面板。

`trace_hash` 对规范 JSON（UTF-8，key 排序，紧凑分隔符，禁止 NaN/Infinity）取 SHA256；哈希内容包含所有请求的到达、类、h/u、T0、deadline，另保存不含 SLO 的 `arrival_shape_hash` 以配对 SLO 扫描。

### 5.4 E19 画像文件合同

`profile_kind ∈ {synthetic,measured_layerwise,measured_total_uniform_layers,public_singleton}`。后两者不能冒充多请求逐层测量；`public_singleton` 只可校验导入和 singleton 曲线，不可供未覆盖批形查表。

每条实测样本必须有：`profile_id,source_url,source_revision,device,device_count,model_revision,dtype,quant,tp,pp,layout,kernel,graph_mode,layer_id,layer_type,h_list,u_list,tokenizer_revision,token_ids_sha256,repeat_id,elapsed_s,peak_memory_gb,measurement_boundary`。不存在的元信息填 null 并标待核实；不能用 0 代替未知。

完整时间或 TTFT 不能直接平均到 L 层并命名实测 layerwise。确要均分，仅可生成 `measured_total_uniform_layers` 新 profile，作为独立敏感性面板。GPU 资料不能改名为 NPU 画像。

首轮画像网格：n∈{1,2,4,8}，请求来自 §5.1 四类；枚举四类计数向量之和为 n 的所有多重集合，过滤硬容量。另有四个 h=2048/u=128 的校验点。合成模式对全部可行形状直接算真值，不拟合；真实设备对同一形状先 warmup 10 次，再测量 30 次，取中位数作真值目录，同时保留原始重复值。

画像预测首个可复现替身采用最近邻：特征 `log1p(n,N,Σu²,Σhu,max(u),max(h))`，训练集逐维 mean/std 标准化（std=0 取 1），欧氏距离最小，同距按形状规范键；只用同硬件/模型/执行栈/层类型分组数据。精确键命中直接用训练中位数；缺覆盖时记录最近邻距离和 OOD，不跨设备补值。

按形状规范键 SHA256 转整数 mod 5：0 为留出形状，1–4 为训练形状；重复测量不跨集合。预测误差和候选排序误差见 §11；未达到门槛只允许报告“画像不充分”，禁止把留出点移入训练后仍称留出通过。

**主缓存假设固定为 `frozen_history_catalog`。** 每文件设 `D_raw=(max_timestamp+1)/1000`，按原时间切分：`[0,0.2D_raw)` 建目录，`[0.2D_raw,0.4D_raw)` 训练，`[0.4D_raw,D_raw)` 正式评价。三个文件的 hash 命名空间隔离，不做跨文件命中。目录只由前 20% 请求的完整块构成，预先驻留在共同存储中，不计建目录成本；运行期间不增删目录。这正对应主模型的固定放置与固定命中，防止调度快的一方获得更多缓存命中、把另一项机制混入收益。

实现为 prefix trie：插入每条建目录请求的完整 hash 前缀路径；查询请求从首块沿同一路径走，遇首个缺块停止。不能用“多少 hash 在全局 set 中出现”代替连续前缀匹配。若命中 k 个完整块，取 `h=min(512*k,input_length−1)`、`u=input_length−h`。末项保留至少一次末 token forward 的工作量；发生时记 `full_hit_last_token_adjusted=true`，并报告次数。该约定是本研究执行抽象，未声称发布方缓存实现如此。

禁止用未来请求构建目录、按每个策略完成顺序重算 h，或把首次出现的全部 hash 都当 hit。若研究动态缓存，必须单独设计；当前所谓“trace 驱动”是**真实到达/长度/前缀结构 + 冻结缓存假设 + 合成计算画像**，并非 Mooncake 服务性能复现。

导入器先对全文件生成特征和校验报告，再分训练/评价，T0/SLO 统计只使用训练区间；建目录区间不能用于算法效果打分。本次用上述目录规则检查 `[0.2D_raw,D_raw)`，可作为导入验收指纹：

### 5.6 真实 trace 的时间缩放、分块与统计重复

每文件训练区间等时切 5 块，标号 0–4；评价区间等时切 15 块，标号 100–114。边界左闭右开，同 timestamp 整组按边界归属，不拆组；块内不足 1 个有效请求报 `insufficient_data`，不从别块借请求。三份 trace 可能来自相关流量，不能把三个文件视为三个独立生产环境。

真实 trace 的 `seed` 字段在 CLI 中映射上述**窗口编号**，不重新生成到达、不打乱顺序。同窗口各策略完全配对；15 个窗口不是 15 次独立采集，应称“15 个不重叠时间块”，用块 bootstrap，而不是虚称 15 独立种子。

每文件用训练请求的经验分布在 B_ref=80 下冻结 `λ0=min(80/mean(V),m/mean(K_singleton))`。正式每块边界为 `[s,e)`，N 为原始请求数，原始平均率 `λ_raw=N/(e−s)`；在目标负载 `λ=ρλ0` 下定义

`scale=λ_raw/λ; arrival_sim=(timestamp/1000−s)*scale; D_sim=(e−s)*scale=N/λ`。

只缩放到达时间，保留同刻 burst 和间隔比例；不改 token、不重算 h、不改带宽或设备速度。另做 `native_time` 面板令 scale=1，不按性能选择性隐藏它。λ0 是统一负载刻度，不是容量保证。

正式块使用整个 `[0,D_sim)`，warmup 为 `0.1D_sim`。不得将短块循环复制到 600 秒以伪造更多样本；实际 D_sim 每块记录。CLI 的 `--duration 150` 在 smoke 阶段只截断已经映射好的到达为 `[0,min(D_sim,150))`，不重新缩放；正式 manifest 使用 `duration_mode=full_block`，600 秒默认值对它不作截断。截断之后同样按实际到达截止的 10% warmup。

原分析“正式 600 秒、warmup=60 秒”仅保留给合成控制变量实验；真实 trace 采用上述有限块模式，避免人为复制和截长。容量面板另用完整评价区间连续重放，不跨块重置资源；只有 §9 的观测时长与积压条件满足，才报告经验容量，否则写“有限 trace 的 SLO/排空边界，容量证据不足”。

## 6. 可观测信息与控制成本

### 6.1 物理真值和调度快照必须分开

`WorldState` 只属于物理执行器和显式 Oracle。普通策略签名必须为 `decide(snapshot: ObservableSnapshot, config) -> JointAction`，不接收 world、storage、env 的引用或返回内部对象的闭包。预测器可以使用相同数学执行内核，但初始化输入必须全由快照重建。

| 来源 | 普通策略可以读取 | 不可以读取 |
|---|---|---|
| 请求 | 已到达请求 h/u、deadline、固定 T0、自己维护的队列 | 未到达请求和未来到达时间表；output_length 不作为决策输入 |
| worker | 空闲/计算/等待、当前批、已完成层、已发生的开始/结束事件 | E24 计算误差模式下的实际未来计算结束时刻 |
| 客户端账本 | 自己提交过的 flow_id、序号、V、提交时间、完成确认 | 资源的精确 remaining、实时内部 active 列表、背景 schedule；计算误差实验中的真实 q/due |
| 存储报价 | `sample_s,delivered_s,bw_hat_gbps,reported_bytes_by_flow,quality` | B(t) 真值访问器、未来断点、`hypothetical_*` |
| 计算画像 | 同一个预测 profile；默认与真值一致 | 扰动实验中仅对优化策略泄露真实 profile |

首轮报价是**理想化可实现接口**，不声称现有 LMCache 指标能直接逐字段提供。默认每 5 ms 采样并立即交付，采样 B 与各自请求的累计字节，无噪声；5 ms 代表刷新周期，不是额外固定传输时延。E24 将 `sample_period` 与 `delivery_lag` 分别扫描。t=0 先发一份合法初始报价，不能等第一条流完成才初始化。

查询成本不随算法查询次数触发新测量：同一轮只能看到最近已交付样本。delay=0 仍经 observable 类型，并非允许访问 world。存储读完成确认即时可见，尚未到达的旧样本不得让已经完成的流复活。

### 6.2 从观测重建预测状态

以最新已交付 sample 为起点，重放客户端账本中 sample_s 之后的真实提交/完成确认、worker 公开事件，带宽恒定为 `max(1e-6,bw_hat)`，推演到 now。当前流剩余量以最近报告字节为锚，之后按预测服务扣减；完成确认强制清零，未确认但预测清零的流保留“预测已就绪”状态并标不确定。所有成员关系和层状态必须来自公开账本。

预测未来带宽常值保持，不推测已知实验的 60/100 秒断点。`pred_singleton_s` 是在空副本中用当前预测带宽和预测 profile 运行一个 singleton 的时间，不含当前队列等待，避免把 queue 重复计入 slack。

预测活动计算剩余为 `max(0,c_hat−elapsed)`。默认计算真值可见模式可用真实 scheduled end；只要开启计算预测误差，所有普通规则、local、MPC 同时切换此公式。Oracle 仍可见真值，但必须另列图例。

计算误差模式也不得从实际 `q=V/c_true` 或引擎真实 due 反推出被隐藏的 c；这些字段只在物理审计日志/Oracle 中保存，普通估计器用 c_hat 重建预测 q/due。已收到的服务进度是合法反馈，不从审计日志回填未来窗口。预测和物理协议因此可能不同，这正是误差来源。

预测所有已知请求无法排空时 score=+∞，不得把未完成者删除后算更好的均值。整个候选都不可评分则返回基础动作并记 `forecast_undrainable`；真实系统继续按自身正带宽演化。

### 6.3 误差模型与三种信息对照

首轮无随机执行噪声，物理 g 与 B 完全由冻结配置决定。E24 改变的是调度看到的预测。

- `current`：上述周期报价；噪声因子 `exp(σ*z−σ²/2)` 乘带宽，z 由 `(scenario,seed,sample_index)` 确定，同轮所有策略共享，σ∈{0,0.1,0.3}。不按候选评分调用次数抽噪声。
- `history`：不收在线容量值，始终用 B_ref=80；保留同样客户端账本和完成确认。它是固定历史参考，不是在各测试格点偷偷读真实 B 的“静态”基线。
- `current_oracle`：读取当前剩余字节和带宽，未来仍常值外推，无未来到达。它是诊断，不叫最优上界，因为有限搜索可能比普通估计更差。

计算偏差 `c_hat=(1+e)c_true`，e∈{−0.2,0,+0.2}，所有普通策略一致。E19 的真实 profile 模式另可用其冻结预测器替代该比例，不叠加未声明误差。误差不修改 T0、SLO 或物理 q 协议。

三情景重放只在 E24：容量因子 `{0.7,1,1.3}`、等权 1/3，H 固定 1，每个动作全部三个情景排空后才参与比较。默认依据期望主 score 排序，再比较最坏主 score。训练若改情景权重必须冻结新配置，不能根据某个动作结果改变权重。

### 6.4 调度控制器的确定语义

中央控制器最多一个正在运行的决策，覆盖所有当前空闲 worker。事件到达时：有队列且有可派发 worker才发起决策；无空闲实例只合并 pending 标志。已有 worker 在 CPU 决策期间继续计算/取数，新到达继续入队，不暂停物理时间。

控制结果在 `decision_start+ctrl_delay_s` 返回，执行 §4.4 既定阶段。验证所有 selected 请求仍在 Q、worker 仍空闲、动作容量合法；联合动作原子成功或整体失败。新请求到达或其他活动批推进本身**不使可行动作失效**，但记 `snapshot_stale=true`；否则高频事件会永久让 MPC 无法提交。资源已变化而动作仍合法时允许落实，并记预测偏差。

若选定请求已被领走、worker 被占用或关键配置版本变更，丢弃结果，记 stale-invalid，立即构造当前基础动作；此回退也收取基础动作控制成本。对同一冲突状态最多重试一次，随后等待下一个正时间事件，不能在零时刻自旋。单控制器正常运行中不会并发双领取，冲突路径仍须单测。

WAIT的wake_at以决策开始时刻为基准；返回时若已经过期，删除该WAIT约束，该worker在下一次合并决策可立即参与。若动作是全WAIT且全部过期，则按当前基础动作回退并计其控制成本，不设置now的自旋timer。

WAIT 仅设置 `wake_at`，不锁请求。任意后续到达/完成/报价可提前唤醒并重评；已有 worker 不受 WAIT 影响。同 worker 只保留最新 generation 的 timer，旧 timer 到点无效。纯 WAIT 必须有严格未来唤醒，超过老化保护时无纯 WAIT 候选。

### 6.5 开销如何进入指标而不破坏可复现性

必须提供三种模式，图表不混算：

| 模式 | 模拟中的 ctrl_delay | 用途 |
|---|---|---|
| `zero` | 0 | 机制理想结果、精确解对拍；不能称部署净收益 |
| `fixed` | manifest 指定每策略固定延迟 | 可严格重放的开销敏感性；默认所有策略相同延迟做成本控制对照 |
| `measured` | 本次 `perf_counter_ns` 计量的实际 decide 耗时 | 同机单进程的实际 CPU 净收益；搜索预算也按实际时间扣减 |

measured 计候选构建、快照重建、评分、gate 与合法性预校验，不计磁盘日志/绘图/JSON 输出。用 `--procs 1` 运行，各策略按窗口编号循环移位执行顺序以减轻热机偏差，记录 CPU/OS/Python/库版本与计时边界。首次 100 次决策作为计时预热另记，**其真实延迟仍进入服务轨迹**。

wall-time 预算有非确定性：measured 结果要保存所有决策选择、返回时刻和输入哈希；用 `recorded` 重放模式读取该动作日志验证物理轨迹，不要求不同机器重新计时得到同一决策。单元测试、解析和候选质量比较使用确定的事件预算 `max_forecast_events=20000`，每处理一个不同时间点的闭包计 1 个事件；不得用机器负载决定测试成败。

搜索默认软预算 2 ms；评不完基础 tail 也必须可返回无预测的合法基础动作。已超预算的半个 tail 或部分情景不更新最优分数。记录 `budget_overrun_s`，不能将软预算上限假装成实际耗时。固定开销扫描为 `0,0.0001,0.0005,0.002,0.005 s`，全策略同成本对照外，再给“复杂算法实测成本、简单算法各自实测成本”净收益面板。

## 7. 在线算法实现合同

### 7.1 共同基础动作、老化保护与排序

MPC/local 的共同 continuation π 固定 `cq_edf`，不随候选、theta 或结果更换；它只是评估尾部的策略，不是 SLO 最优性假设。MPC 的参照首步也是当前 π 的联合动作。独立 FCFS/SPT 等仍按自己的规则运行。

`W_guard=2*train_P95(T0)`，一旦有 queued 请求等待 `≥W_guard`，先取最早 `(arrival,rid)` 的超限请求作为首个空闲 worker 的强制锚点；第一批必须包含它。生成其余 worker 动作时，对剩余超限请求依次应用。无空闲 worker 时无法立即保证服务，必须记最大等待与超限数。所有在线策略都用此 wrapper，强制锚点后按各自排序填批；E20 纯优化问题不加此保护。

量化排序值出现 float 平局时按精确 tuple 顺序，不使用随机打破。候选规范键为升序 rid tuple；联合动作键为 worker 升序的 `(kind,members,wake_at)`，其中 DISPATCH 排在 WAIT 前。

### 7.2 候选请求与批：不留实现自由度

默认 `K_req=32,K_batch=24,J_width=16,beam_width=8,H=2`。按到达、T0、deadline、当前 slack 四个列表轮询各取一个，去重直到 K_req 或无更多请求；每个列表使用 §3 的次级键。强制补入 π 当前完整联合动作的所有成员、所有本轮强制老化锚点，允许超过 K_req，实际数记日志。

对选出的每个 anchor，构造三种顺序，逐项尝试加入合法成员，保留每一个中间批，不只最终满批。这里候选构建可以跳过不合容量的成员，区别于基线填批；最后对成员集合去重。

| 顺序 | 主键，之后统一接 `(arrival,rid)` |
|---|---|
| 同形 | `abs(log1p(h_i)−log1p(h_a))+abs(log1p(u_i)−log1p(u_a))` |
| 互补 | 对正 `r_i=V_i/K_i` 用 `abs(log(r_i)+log(r_a)−2log(r_ref))` |
| 紧迫 | `(deadline_i,arrival_i,rid_i)` |

`r_ref` 为训练集中所有正 V/K 的几何均值，按请求权重；无正值时互补顺序退化为到达序。零读取候选在互补列表排在正比值之后，按到达序；人工零计算/正读取比值记 +∞，排在零读取之后，禁止 log(0)/NaN。

候选预排序键固定为 `(-G_batch, min_member_slack, sum_V/sum_K, members)`，分母 0 用 +∞；取前 K_batch。随后额外保留所有选中请求的 singleton、强制老化批与 π 每个批。超过 K_batch 合法，K_batch 是普通批额度，非总候选硬上限；实际候选数进日志。

### 7.3 联合动作和等待候选

每个空闲 worker 可领候选中的任一合法批或 WAIT，成员不得与其他 worker 重复。等待相对时长取 `{0.05,0.1,0.2}*C_ref`，`C_ref=train_median(K_singleton)`，另加入预测未来最早的读完成时刻、最早下一层提交时刻；只保留在 `(now,now+0.2C_ref]` 内的事件。没有有效预测事件不补猜测点。WAIT 时间再裁到老化锚点达到 W_guard 的时刻；非正候选删掉。

逐 worker 构造联合动作 beam：扩展 DISPATCH 候选及每种 WAIT，按 §7.4 局部完整评分保留 J_width 个部分动作，尚未处理的空闲 worker 在部分评分中视作立即执行 π。完整动作保留 J_width，并额外补 π 完整动作、每一种“全体同刻 WAIT”动作。删去违反老化 wrapper 的动作。同一非零 WAIT 因浮点舍入合并时保留最小时刻。

**信息消融**统一使用历史预测构建候选池和联合动作池，记录 pool_hash，之后仅评分器替换 history/current/oracle。严格matched_pool以同一物理状态的配对快照为单位，具体见§9.7；不同策略独立闭环执行后状态会分叉，不能要求整个运行的候选池仍相同。完整算法默认允许按自身观测构建候选，这个面板比较的是总效果；两者分别命名 `matched_pool` 与 `end_to_end`。

### 7.4 score、局部对照及词典序

某次决策的已知集合 K 为所有 `arrival≤now` 的未完成请求，加上本次搜索前已完成请求的固定贡献。候选评估不读未来到达；各分支对同一个 K 排空，完整计算 F。可以省略已完成的常数项，但日志分母必须一致。

最小化词典序：

| theta | 排序 tuple |
|---|---|
| M | `(max F, sum TTFT, action_key)` |
| S | `(failure_count, sum TTFT, action_key)` |
| T | `(sum TTFT, failure_count, action_key)` |
| R | `(sum TTFT/T0, sum TTFT, action_key)` |

原问题的目标仍是 tuple 第一项，其他项只打破平局。SLO 恰好到期算成功。动作总效应使用 `J(base)−J(candidate)`，M 不能用“请求最大提前量”替代。

`cq_local` 使用同一个 K、候选池、tail 和目标 tuple，但预测时将每个 worker 的存储带宽独立设为同一个 B_hat，不计跨 worker 竞争；本 worker 内层依赖、批同步、q_max 和完整 tail 全保留。它仅是忽略共享干扰的评分消融，真正执行时仍走共享 FCFS。因此 local 与 global 的差值可以定位跨实例建模价值。

### 7.5 MPC 主过程

```text
snapshot = observable_only_state()
base_action = guarded_EDF(snapshot)
best_first_action = base_action
base_tail = forecast_to_drain(base_action, pi=guarded_EDF)
if base_tail 没有完整评分: return base_action，记 fallback
best_score = score(base_tail)
beam = [(snapshot, empty_prefix)]
for depth in range(H):
    expanded = []
    for node in beam:
        batches = build_batches(node)
        actions = build_joint_actions(node,batches)
        强制保留 node 当前合法的 pi 动作
        for action in 固定顺序(actions):
            if 已用尽预算: 转到门槛检查
            child = 估计状态深复制后落实 action
            推进至严格未来的、可决策的到达/完成/观测/唤醒事件
            tail = 从 child 用同一 pi 排空所有已知请求
            if tail 未完整或多情景不齐: 丢弃该评分
            else:
                按 theta tuple 更新最佳完整方案
                expanded 加入 child、prefix、完整 score
    beam = expanded 中 score 最小的 beam_width 个
    同时保留合法基础延续分支；无分支则结束
gate 后只返回最佳方案的第一个当前动作
```

假设未来没有外部到达时，π 遇到有队列且有空闲 worker立即派发；预测尾部不存在等待未来请求凑批。基础分支的完整排空永远参与比较。深层动作不直接预订或提交到真实系统。

改善门槛默认 zero 模式为 0；只有主目标严格改善才从 base 切换，不因纯次级目标平局启动一次新 WAIT。稳健版本的门槛在训练上标定：T 用基线一轮预测与实际完成均值误差绝对值 P95，R 用归一化均值残差 P95，M 用 max-F 残差 P95，S 用满足率残差 P95。校准以训练中真实落实的决定为样本，仅表示工程保守门槛，不能宣称反事实误差保证；样本不足 100 则 gate=0 且标 `uncalibrated`，不得标已通过鲁棒门槛。

threshold 与 score 统一到“每请求均值/满足率”后比较，避免总和随着队列长度增大改变 gate。小规模真值对拍不使用该门槛，四种目标分别输出。

### 7.6 首轮不实现的自由扩展

原分析的局部交换/拆并批搜索可后续新增 `cq_local_improve`，当前不属于 `cq_mpc` 默认行为。chunk、跨请求读取去重、并发第二活动批、prefetch、动态重算、KV 放置、预测未来到达也不在首轮合同中。新增这些动作必须先写共同能力规格和对应实验，不能以“优化细节”直接混入主结果。

## 8. E20 精确参照：网格最优与证书

### 8.1 输入空间和时间边界

解析主例为两 worker、两层、两个 long 和两个 short，全部 arrival=0，long 每层 `(V,c)=(4,2)`，short `(1,1)`，batch c 为成员 c 之和、V 为字节之和，q_max=B=4，batch 上限 2。T0_long=5、T0_short=9/4，deadline 分别 15、27/4。

扩展人工实例 n∈{4,6,8}，按字典序枚举长度n的全部二进制类型向量，0为short、1为long，共2ⁿ个输入（同类型身份仍保留rid），n_max∈{1,2}；全到达0，B∈{2,4,8}。首轮正确性小集固定 B=4，不把整个笛卡尔积列为单测。加入一组 arrival=`(0,0,1,1,2,2,3,3)` 的前 n 项作为不同 release 回归。

目录包含全部合法 singleton/pair，不做候选剪枝。启动网格步长 δ∈{1/2,1/4,1/8} 秒，内部读算事件用精确 Fraction，不量化。网格终点由“所有 singleton 按 rid 在 worker0 串行执行、每次领取向上取整到 δ 网格”的计划最后领取时刻确定；该计划构成必有可行解的 UB 初始候选。所有待比较策略共用该网格终点，不按自身计划改终点。

主表对固定网格求四目标；δ/2 与终点+2δ 为敏感性单独列。改细网格允许更好解，但不得用粗网格 LB 给连续启动 MPC 证明 gap。精确对照时普通规则/MPC 的领取和 WAIT 全都对齐同一网格，未来信息差异明确标注。

### 8.2 首版可证明下界

为了先保证正确，可先采用保守下界，不能用高估的启发式提升剪枝率。

对于当前 t，每个 DONE 请求 e_i=F_i；ACTIVE 请求的 e_i 为 t 加其剩余纯计算时间，忽略所有读取；QUEUED/FUTURE 请求的 e_i 为 `max(t,a_i)+min(Kβ:β包含i且β所有成员尚未领取)`，忽略伙伴 release、worker 占用和所有存储。目录含 singleton，最小值总存在。令

- `LB_T=Σ(e_i−a_i)`，`LB_R=Σ(e_i−a_i)/T0_i`；
- `LB_S=Σ 1[e_i>deadline_i]`；
- `LB_M=max(max e_i, t+K_rem_lower/m, t+V_rem/B)`，B 为该 E20 恒定正容量。

`K_rem_lower` 为 ACTIVE 的剩余纯计算，加所有未领取请求各自 `min(Kβ/|β|)`；`V_rem` 为全部尚未传输字节，包含活动流剩余与未来层和未领取请求的读取。三项取 max，不相加。若全部已完成直接返回实际目标。为保守起见未领取目录可包含尚未来到的伙伴，但不能把 ACTIVE/DONE 成员复用进去。

此下界不要求紧；网格限制被放松只会更乐观。E20 额外逐状态验证 `LB≤穷举该状态真实最优`，通过后才启用剪枝。零带宽边界不使用除法下界，而走显式不可排空分支。

### 8.3 枚举、B&B 与超时

无剪枝枚举和 B&B 使用同一全动作生成器：按 worker 编号递归 DISPATCH 全合法批或 WAIT 一格，包含全 WAIT；已占用 worker 不分支。最后一格后还存在未领取请求则分支不可行；全已领取则继续排空，可在网格终点后完成。

B&B 选 `(LB,depth,node_id)` 最小的 OPEN 节点，节点在**全部子动作生成完前**保留 OPEN，避免超时丢失尚未展开区域。剪枝条件仅 `LB_primary≥UB_primary`，不把普通策略评分当 LB；相等时可以保留 incumbent，不保证次级 tie 最优。无额外 worker 对称合并、不做浮点 LB 剪枝。

超时返回 `status=time_limit,LB=min(UB,所有未完成区域LB),UB=最佳重放可行值`。OPEN 空才可 `status=optimal,LB=UB`。无可行 incumbent 时 UB=null、状态不是 optimal。分别做 1/10/60 s 搜索预算，所有中间证书保存；单元测试用节点预算控制确定性。

最小化连续值的证明 gap 为 `(UB−LB)/LB`，仅 LB>0 时报告。S 用失败数区间 `[LB_S,UB_S]` 和可能多失败的人数；LB=0 不写百分比 gap。普通方案 J≥LB，若 J<LB 则属于证书/问题口径错误，立即停止发布。

保存输入、目录、网格、最优/候选计划、节点计数、OPEN 最小 LB、数值模式、solver 版本；仅保存一个“optimal=true”字段不构成可检查证书。

### 9.4 E21：组批收益和同步损失

**要回答**：batch 节省的计算是否转化为请求收益。

主输入从每个 Mooncake 评价块取最前 128 条请求，不足128则全部保留，h/u 和固定目录不变，将这些请求 arrival 全设0并按相同SLO时长重设deadline=`α*T0`；这是 **Mooncake 形状驱动的有限工作集**，必须与 E23 的真实时间回放分名。不截 token。每份输入分别运行四目标，控制模式 zero；另在默认 profile 加 measured 复核。训练对应使用0–4训练块的前128条，不能用评价形状选择B*。

组批能力对照分三块单独做，不能横跨块归因信息价值：

| 能力块 | 所有被比较策略共有的约束 | 作用 |
|---|---|---|
| A singleton | n_max=1 | 无 batching 的完整参照 |
| B homogeneous | 同一批成员必须同属 `(h≤train_median(h),u≤train_median(u))` 四象限之一 | 限制混批；边界等于阈值放低侧 |
| C unrestricted | 只受共同人数/token/内存约束 | 自由混批的总价值 |

每块比较 FCFS、LPM、SPT、EDF、Slack、Pair、Local、MPC；B* 在对应能力块训练后冻结。默认 B=80，第一轮扫 profile∈{无合批加速,N_sat=128,512,2048}，其他参数相同；再固定 N_sat=512 扫 B=20/320。禁止做全部交叉后只挑最漂亮格点。E21相对SLO固定α=4，各profile自身生成T0并另记SLO组；跨profile只作效率敏感性，不声称只改计算却保持绝对SLO不变。

输出按组：原始 M、满足率、均值与归一化均值；实际批人数分布、ΣK_batch、G_batch 分布、短 u/长 u 分组 TTFT、总字节相等校验。主图 `fig_e21_batch_tradeoff.png` 同屏放“计算秒下降”和“短请求 TTFT/SLO”，避免用 Compute 占比一项宣布胜利。

### 9.5 E22：排序与错峰的因果隔离

**要回答**：一次延迟领取如何改变其他 worker 的 FCFS 排位和完成时间，等待有没有仅从 STALL 搬到中央队列。

两层证据必须都有。

**A. 固定批的确定算例。** §11.2 的 P1→P4，仅把 LL 的领取从0改为0.5；LL 的请求仍在中央。画完整提交序号和每段实际带宽，验收正确的数值不是“必须所有指标改善”。额外将 delay 扫 `{0,0.125,0.25,0.5,0.75,1}`，B∈{2,4,8}，成员不变；每格全部保留。

**B. Mooncake 固定批工作集。** 使用 E21 同一128条输入；按 FCFS 在原限制下预先分批，形成固定批目录（singleton 也不得另拆），用此目录训练/比较，只研究批的选择次序和领取时刻。固定目录是调度计划数据，不是本地预订；领取前所有请求仍在中央。

四种策略：`fixed_immediate` 按目录顺序给空闲 worker立即领取；`fixed_phase` 使用固定顺序且 worker w 只在 `k*P+w*P/m` 网格领取，`P=train_median(K_fixed_batch)`；`fixed_order_mpc` 允许重排目录但立即用满所有可领取的空闲 worker；`fixed_wait_mpc` 允许同样重排再加 §7 WAIT。以 B=20/80/320、四目标运行，计入所有延迟。固定相位不能凭空预取，也不能把相位期间中央等待删掉。

固定批模式的guard锚点要求领取“包含该请求的目录批”，不重新组批；P的训练批来自同文件训练块的同一FCFS分批函数，α=4。固定相位主因果图使用zero成本，追加measured对照；相位绝对时间由t0=0起算，k为非负整数。instant/order/wait与phase的可选启动集合不同，这一组明确标为timing能力对照，不用于信息价值证明。

普通 `cq_mpc` 动态组批另画为总收益，不参与“只改变 timing”的差值。拆分时顺序为 immediate→order→wait，每条边只改变一个自由度。即使某条边为负也必须画。

每请求输出 `Δqueue,Δcompute,Δstall,ΔTTFT`，相对于 fixed_immediate；逐请求恒等式 `ΔTTFT=Δqueue+Δcompute+Δstall`。固定成员的 Δcompute 必须为0；若不为0，说明 profile 或成员被改动，run 无效。主图 `fig_e22_timeline.png` 与 `fig_e22_wait_decomposition.png`。

### 9.6 E23：Mooncake 主收益、负载与 SLO

**要回答**：保留真实 burst/长度/复用结构后，比 FCFS 和 B* 好多少。

主矩阵固定为三个本地文件 × B∈{20,80,320} × ρ∈{0.3,0.6,0.9,1.1} × α∈{2,4,8} × theta∈{S,T,R} × 15评价块。策略为 §3 全部普通策略（7个简单/局部 + MPC，共8个）；每个 run 用同一 h/u、arrival 和 SLO。做 zero 与 measured 两套，预算不足导致回退是有效结果，不删除该格。主 run 清单预生成，失败重试使用同一 run_id，不能重复计样本。

为限制额外矩阵，固定 SLO 对照仅取 α=4、B∈{20,80,320}、ρ∈{0.6,0.9}；native_time 面板使用 B=80、相对α=4、三个 theta、全部15块。两者都对所有普通策略执行，不只挑 MPC。

报告 P50/P95/P99 TTFT、满足率、goodput、归一化均值、分组、未完成数、控制耗时和队列曲线。在线 M 仅作为停止到达后固定 cohort 的描述性指标，不用“无限流全部完成时间”。四目标齐全由 E20/E21/E22 的有限工作集提供。

**经验容量面板**：每文件完整 `[0.4D_raw,D_raw)` 连续重放，用相同缩放公式扫描 ρ∈{0.1,0.2,...,1.5}，α=4、B=80、theta=S，对 FCFS/B*/MPC。不对每策略单独扩展搜索到它最好看的范围。满足以下全部条件的最大已测 λ 才称该 trace 的经验可持续 SLO 负载：

1. 有效 steady 窗口≥`max(60 s,1000*train_median(T0))` 且 cohort 至少1000请求；不足则容量为 null，仍显示有限窗口负载曲线。
2. SLO 满足率≥95%，无截止排空预算后的未完成者。
3. steady 窗口按20个等长区间统计 Q+ACTIVE 请求数，在前10段和后10段分别做 OLS backlog 对时间斜率；二者均≤`max(0.01*λ,1/H)` req/s，防止前期清空掩盖后期积压。
4. 最高满足点之后至少有一个更高负载失败；若扫描上界仍通过，只报容量≥已测上界。

这是有限 trace 的经验判据，不是排队稳定性证明；native burst 可能使容量不是严格单调，必须展示全部曲线并注明非单调格点。正式相对收益主要依据三文件的分块主矩阵，不把有限容量面板当独立多种子证据。

### 9.7 E24：信息、搜索、能力与误差各贡献多少

先用measured模式训练结果确定两类锚点，不读取评价效果：每个 trace 选对应 B* 在 theta=S、α=4 下满足率20%–95%、并且 STALL/(Compute+STALL)≥20%的 `(B,ρ)`，按 `(|满足率−0.7|,B,ρ)` 选最小者。无满足格点则标 `no_interaction_anchor`，采用预定 `(20,0.9)` 作负面诊断，不能声称已找到作用区间。另固定 `(320,0.3)` 为松负载对照。

每个锚点各自做下列一因素扫描，不取整表笛卡尔积；theta 取 S/T/R。

| 面板 | 扫描项 | 固定项/比较规则 |
|---|---|---|
| 信息 | history/current/current_oracle | 配对快照matched_pool，H=1、候选/预算/硬能力相同；另给完整闭环面板 |
| 更新周期 | 0/0.005/0.020/0.100 s | delivery_lag=0；0为每个物理事件发布，仍过接口 |
| 交付滞后 | 0/0.005/0.020/0.100 s | sample_period=0.005 |
| 带宽噪声 | σ=0/0.1/0.3 | 同 trace/样本共享 z；默认其余观测参数 |
| 计算偏差 | e=−0.2/0/+0.2 | 所有普通策略对称应用，真值不变 |
| 搜索预算 | H=1/2/4；K_req=16/32/64；J_width=8/16/32 | 每次只改一项，其他默认；同时报告超预算/回退 |
| 硬能力 | batch=1；同象限；禁止WAIT | 每格对所有策略同时限制；重新训练该能力的 B* |
| 控制开销 | §6.5 固定延迟扫描、measured | 同成本控制组与各自实测组分开 |
| 非平稳 B | `((0,B),(0.4D,0.5B),(0.7D,B))` | D为该trace块有效到达跨度；合成诊断用60/100秒断点 |
| 申请协议 | deadline-boost / periodic-catchup | 同一协议内比较全策略，绝不单侧换协议 |
| 连接上限 | q_max=40/200 | 组间可重算参考T0并另记SLO组；组内固定 |

周期追赶协议固定每1 ms从该流提交时刻起更新：到期前 `q=min(q_max,remaining/(due−now))`，到期后 q_max；V=0不建流、due=now直接q_max，更新不改序号。同刻与完成相遇先处理完成。首层始终q_max，无额外追赶timer。该组只改变协议，不能混入主 FCFS 成绩。

三个情景稳健版与单情景对照放在带宽σ=0.3和非平稳B面板，H都固定1以隔离情景作用。给 `gate=0` 与训练 gate 两条曲线。末图 `fig_e24_robustness.png` 标出收益过零点与最频繁 fallback 原因。除配对快照外E24一因素主扫描使用zero模式，默认配置及控制开销面板追加measured；headline复用E23相同格点的measured结果，不重新挑窗口。

matched_pool快照库由冻结B*在该评价块的执行生成，每轮存在队列和空闲worker时记录快照，按决定序号取前100个；少于100则全取。保存同刻物理状态供实验执行器克隆，普通策略仅获其对应观测。用history预测构建一次公共候选/联合动作池，H=1、事件预算20000、gate=0；各信息评分器分别选首步，再由实验执行器从同一真值状态重放该首步，随后统一guarded_EDF排空当时已到达集合，无未来到达。主差值为这一步造成的真实目标差，先在一个窗口内取中位数，再在15窗口统计，避免把同一trace的100快照当100独立样本。pool_hash只在同snapshot_id的比较中必须相同。

完整闭环history/current/oracle使用同参数和能力，但允许物理轨迹、候选与后续状态自然分叉，标end_to_end；只要求入口数据/配置可比，不宣称全过程候选完全相同。

### 9.8 冒烟定位与有限的调参规则

冒烟用各文件训练块0、1，`--duration 150`，B=20/80/320、ρ=0.6/0.9、α=4、theta=S/T；先跑 FCFS、SPT、Slack、MPC，zero模式，再补 measured。同时运行 E20 P1–P4。

单实验smoke的确定子集：E19只做三文件导入和公式画像；E20做P1–P4及n=4、类型0011、δ=1/2的枚举/B&B；E21取每训练块前32请求、B80、α4、theta=T、默认与无加速profile；E22做P1/P4和同一32请求固定目录、B20/80；E23采用上一段主冒烟网格；E24在尚未训练锚点时固定B20、ρ0.9、α4、theta=S，比较5/20ms观测与0/0.5ms固定控制成本。smoke的B*/gate未冻结，图只用FCFS参照且不输出研究go。

至少两个 trace/格点中简单强基线处于20%–95%满足率，并能从 FCFS流量、STALL和backlog解释瓶颈。若达不到，训练阶段只允许一次扩展 `B∈{5,10,640},ρ∈{0.1,0.2,1.3,1.5}`，其他参数保持；扩展后仍无作用区间，则记录研究目标不匹配/无区分度，正式负面结果可以继续，但不能标正面 go。

不允许用缩短大请求、提高 MPC 独享内存、改变 cache hit 或只收紧某一策略 SLO 来获得区分度。正式 manifest 必须包含初始网格全部格点及采用的扩展格点，不能删掉初始负面结果。

## 10. 指标、收益计算和结果文件

### 10.1 cohort、窗口与截断

有限工作集所有请求都计入，t0=0。在线 cohort 为 `[warmup,arrival_stop)` 到达的请求；warmup 前请求正常执行并干扰资源，但不进该 cohort 的时延/SLO分母。资源统计窗固定 `[warmup,arrival_stop)`，排空期另计，不按每策略 M 改变在线资源分母。

排空预算 `drain_budget=max(600 s,10*train_P99(T0))`，截止 `arrival_stop+drain_budget`。所有普通策略不得丢弃超期请求，过期请求仍参与 EDF/slack 排序和老化保护；无人工 kill 来提高 goodput。

未完成请求的 TTFT 是右删失。保存 `F=null,censor_time,ttft_lower=censor_time−arrival`；整 cohort 的均值和归一化均值报告**下界**，完整值为 null，另给 completed-only 诊断但不参与收益胜负判定。P95/P99 用全 cohort 的完成值与未完成 lower bounds 算下界，带 `is_lower_bound`；不把失败者排除。

到截止仍未完成且其 deadline≤截止者确定SLO失败；deadline>截止者状态 unknown，报告满足率区间 `[success/n,(success+unknown)/n]`。研究 go 不能用含 unknown 的点。已完成但超deadline一律失败。

### 10.2 核心和解释性指标

| 指标 | 定义/分母 |
|---|---|
| TTFT_i | `F_i−arrival_i`，包含中央等待和控制延迟 |
| 归一化 TTFT | 每请求 TTFT_i/T0_i，再算平均；不取两个平均的比 |
| 满足率 | cohort中F≤deadline的人数 / cohort到达数 |
| SLO goodput | 上述按时人数 / `(arrival_stop−warmup)`，单位req/s；按到达cohort计，不以完成窗重选请求 |
| 有限 M | `max F−0`；若有未完成，值为null、记录已知下界 |
| batch G | `Σ成员singleton K / batch K`；汇总同时给按批分布和 `Σsingleton K/Σbatch K` |
| E_token | 新token数 / batch纯计算秒；不是完整生成吞吐 |
| 设备分解 | 固定窗各worker状态积分之和；Compute+STALL+Idle=mH |
| 存储利用率 | 窗口内传输GB / `∫B(t)dt`；分母为0时null |
| 满足申请比例 | 时间积分Σactual / 时间积分Σrequested；分母0时null |
| 排队 | Q与Q+ACTIVE随时间、最大等待、guard触发/超限次数 |
| 控制开销 | decide P50/P95/P99、总CPU秒、超预算率、回退率、过期可行动作率 |

按三个 source 单列，再按 h/u 训练中位数四象限、按 T0 训练P50/P90定义的短/中/长服务类分组。实际正式分组可能有空类，n=0显示null。不能按测试时延给请求重新分短长，也不能只画全局均值。

### 10.3 相对收益的唯一公式

对每个相同窗口/种子 k、相同场景、目标和成本模式，基线 b 与算法 p 配对：

`latency_gain_k=100*(J_b,k−J_p,k)/J_b,k`，J为完整M/平均TTFT/平均归一化TTFT，且J_b>0。

`slo_gain_pp_k=100*(A_p,k−A_b,k)`；`goodput_gain_pct_k=100*(G_p,k−G_b,k)/G_b,k`。基线goodput=0则相对比为null，只报增加req/s和百分点。负收益必须保留。

显示 `median(gain_k)`，不能用 `gain(median(J_b),median(J_p))` 代替配对中位数。表中同时保留两边原始指标中位数与配对差值，避免用户只看到百分比。

合成独立种子：对15个配对种子重采样10000次。Mooncake时间块：在15块的原始时间顺序上做循环 moving-block bootstrap，块长3，抽5个起点并各取连续3块共15项，计算配对中位数，重复10000次；首尾循环仅用于统计抽样，**不用于仿真拼接**。使用 `PCG64(20260915)`；区间取2.5/97.5百分位，`numpy.quantile(method='linear')`。它反映同一文件的块间不确定性，不能声称覆盖不同生产日期。

### 10.4 输出目录和 schema

每个 run 的最小路径为

`results/cq/<stage>/<manifest_sha256>/<exp>/<scenario_id>/<cost_mode>/<theta>/<policy>/<window_or_seed>/`。

scenario_id取不含policy/window/cost_mode的规范化物理与workload配置SHA256前16位，登记表若发现前缀碰撞则报错并改用完整hash；不能覆盖目录。trial运行写临时目录，所有文件落盘与校验完成后原子改名；重跑已完成run需校验哈希相同并显式记录attempt，不混入两份摘要。

| 文件 | 必须字段 |
|---|---|
| `manifest.json` | schema_version、git_sha、dirty、config/profile/source/trace/catalog/pool hashes、stage、theta、policy、cost_mode、seed或window、全部解析后配置、source provenance、版本环境 |
| `requests.jsonl` | rid、source_file/line、source_timestamp_ms、a、h/u、input/output_length、T0、deadline、group、batch_id、dispatch、F或null、queue/compute/stall、SLO状态、censor字段 |
| `batches.jsonl` | batch_id、member_ids、worker、dispatch/F、逐层g、MemPeak、G_batch、profile_id |
| `flows.jsonl` | flow_id、batch/layer、submit_seq、A/R、V、due、每个q变化事件、每段rate与remaining |
| `worker_segments.jsonl` | worker、start/end、state、batch/layer、idle_reason |
| `decisions.jsonl` | now、version、snapshot_hash、candidate/pool hashes、actual counts、theta、base/best完整预测、gain/gate、首动作、wake、ctrl耗时/返回时刻、预算与fallback |
| `summary.json` | cohort/window、全部原始指标、各类分组、censored/unknown/invalid、conservation残差、回退和成本 |
| `solver.json` | 仅E20：grid/catalog、数值模式、LB/UB、状态、nodes、计划路径与重放结果 |

summary 的 Infinity/NaN 一律转 null 并附 status/reason，不能写非标准 JSON。时间字段统一 `_s`、字节 `_gb`、带宽 `_gbps`；上表缩写在实际 schema 中展开。每个文件第一版 schema_version=1，后续不兼容修改升版本。

精确校验和E22全量保存事件。E23/E24至少保存所有请求、批、summary、决定摘要；高频流/worker完整事件对固定代表窗口100及所有invalid运行保留，其余可用gzip流式存储，summary由运行时精确累计。不能因为关闭日志改变事件数预算或动作。

聚合器必须核对可比双方 trace、profile、capability、protocol、SLO、cohort、cost_mode 哈希相同；matched_pool配对快照额外核对snapshot_id/pool_hash，闭环运行不要求相同pool。profile可比性指物理真值profile_hash，预测器另存prediction_hash，信息消融允许它不同。缺少一方不能配对，用 missing 表列出，不做邻近窗口替补。

### 12.4 正确性、证据质量和研究判断分层验收

**正确性硬门槛**：§11全部不变量通过、全量旧测试通过、无重复领取/漏字节/未来信息、四计划逐数吻合、小实例B&B与完整枚举一致。任一失败，不能发布性能结论。

**证据质量门槛**：三份本地trace都有导入provenance和正式面板；有配对原始值、截断/unknown、负收益、B*冻结记录；图片嵌入；合成g的局限明确；画像未达到门槛不能写硬件go。未完成全run清单不得以子集冒充整个E19–E24完成。

**研究go的预注册headline**：E24按训练规则为每个文件选出的interaction锚点、α=4、theta=S、measured模式，共3个headline格点。相对各自冻结B*，至少2个格点SLO提升中位数≥5pp且配对95%CI下界>0；同时报告对FCFS收益。另在相同3格点分别运行theta=T/R并用对应B*，若时延下降≥5%且CI下界>0可记该目标go，不能用T获胜替代S满足率未达标。文件间不作独立生产数据的统计宣称。

因存在3个headline比较，报告原始95%CI外，追加Bonferroni的98.333333%区间；严格headline成立要求相应校正区间下界仍>0。T、R各作为独立目标家族，其他全网格点为边界探索，不宣称未经校正的每点显著性。

出现以下情况分别标明：

- `mechanism_go / deployment_no_go`：zero有收益，measured未达门槛，或决定P95>`0.01*train_median(T0)`。首轮synthetic服务很快，2ms可能明显超预算，不能隐去。
- `quality_unproven`：小实例只有松LB/timeout，不能宣称近最优；即使线上有收益也保留此项。
- `fairness_regression`：headline任一至少30请求的长服务类，其P95相比B*恶化>10%，或满足率下降>5pp。总收益保留，但不能给无保留部署go。
- `no_go`：净收益不达预注册门槛。接受负面结果，停止在测试集上继续调参；下一版研究须新设计和新评价划分。

小实例near-optimal质量目标为原目标证书gap≤5%，只统计获得证书的适用实例，并同时给全部实例的证书覆盖率；不能剔除timeout后声称普遍近最优。

## 14. 通俗版解读

把三个Mooncake文件想成三本真实订单登记簿，里面有订单到达时间、要做多少新工序，以及哪些旧材料可能复用。我们先用较早的记录建一个固定档案库，再让所有调度方法处理相同的后续订单。档案库不因谁先做完而偷偷变大，才能公平比较安排工作本身的价值。

几座加工台共用一条供料带，每台一次只做一盘。FCFS先做先来的订单；SPT先挑预计较短的；预算排序先照顾快到交期的；全局方法会预测这盘料单插入队列后，其他加工台会等多久，再决定是否合盘或稍等一下。

E19检查登记簿和加工时间尺是否可信。E20用小订单逐步算账，确认模拟器和最优参照没算错。E21看合盘省下的加工时间是否值得让小单陪跑。E22看延迟半步有没有真的保护别人取料。E23回放三本订单簿，直接看比FCFS和强简单规则快多少、多按时交多少。E24故意让信息变旧、决策变慢，找出复杂方法应退回简单规则的地方。

最终结论应能落到具体场景：哪类订单和供料压力下值得做，付出了多少调度成本，谁得益、谁受损，以及哪些地方目前仍只能由合成加工时间支持。
