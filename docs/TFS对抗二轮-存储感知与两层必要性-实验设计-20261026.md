## 术语

- **物理设定攻击**：攻击对象不是请求到达序列，而是场景的物理参数——块在盘上的落点分布、背景流量窗口、带宽时间曲线。第一轮的攻击全部是请求序列攻击。
- **盘感知臂（TFS-D）**：在 v3 之上把「一条总带宽账本」换成「每盘一本账」的调度器。本轮新建，用于回答 Q1 的对照。
- **prefix（前缀键）**：一个请求的缓存前缀标识。引擎按它做块→盘的确定性哈希。合成负载下 prefix = `类名:h_tokens`，公开可推导。
- **块计划（disk_plan）**：某前缀的块落在哪些盘、各多少字节。确定性纯函数，`sim/cq/storage.py` 文档明示「任何策略/推演可重建同一计划」。
- **必要性判据**：见 §2.4 与 §3.1，双向预注册。

## 1. 问题定义与第一轮为什么答不了

**Q1（存储状态）**：TFS 系（v0~v3）看存储只看两样：报价带宽（每 5ms 一个数）和在跑请求自己的 d 值。更细的状态（每盘占用、在途流剩余字节、背景流量位置）从未进入决策。第一轮 134 轮的攻击武器是请求序列，**盘模式只在 2 轮里被顺带用过，从未作为攻击面**——所以「零击杀」不构成「不需要」的证据。反向也成立：E26f 盘维度实验量化过总带宽利用率 −7.3pp、小读类长尾 +14%，但该实验里**所有策略都看不见盘**，也没有「看得见盘的臂」来兑现这 7.3pp——所以也不构成「需要」的证据。

**Q2（两层）**：两层规则（TFS-G/TFS-E）只在 `adv/two_layer.py` 参考引擎上被攻击过（第一轮 G10~G13、W3/W7/W8），大部分未分出胜负。参考引擎的批语义是自建近似，分辨不出的地方不能推论「两层不必要」。已有的两个方向性数据点：过载档上两层臂 24~31% 对单层下放臂 4~6%（第一轮 r12/r15 实测）；反压误触 bug 只在单层下放语义下爆炸。

## 2. 线 A：存储状态必要性（本仓库引擎内闭环可答）

### 2.1 信息可得性（关键：不动信息边界）

盘感知臂需要的全部输入已经是公开量，对称地摆在那里：

1. 块→盘落点：`disk_plan(prefix, h, disks)` 纯函数，策略可直接调用（与引擎同函数同结果）；
2. prefix：合成负载下 = `类名:h_tokens`（`engine.py::_members_h` 文档：公开确定性信息）；
3. 在跑流剩余量：`PublicFlow.V_gb` 与 `served_reported_gb`（公开）；
4. 盘数与单盘容量：场景的带宽曲线 ÷ 单盘带宽派生（`scn.storage` 在 decide 的参数里）。

**结论：不需要扩 Observable，信息边界零变更。** 所有臂（含基线）面对同一物理与同一公开函数，公平性保持。

### 2.2 盘感知臂 TFS-D 的设计

在 v3（七个开关全开）之上替换第 3 步「总账本」为「每盘账本」，其余六步原样：

- **每盘账本**：`ledger[盘] = Σ 在跑大读(未进末层) 的 d_i × frac_i(盘)`，其中 `frac_i(盘) = 该请求块计划中落在此盘的字节 ÷ 总字节`；
- **放行条件**（替换 v3 的单条 Σd≤cap）：对候选大读，**每一盘**都满足 `ledger[盘] + d_c × frac_c(盘) ≤ 单盘容量 × 1.1`（单盘容量 = 当前报价带宽 ÷ 盘数；容差与 v3 的 1.1 一致）；
- **唤醒**：同 v3（最早在跑大读进末层的时刻；不做每盘精细唤醒——第一版保持最小差分）；
- **同构性自查**（local 崩塌教训，E26f §6.2）：账本口径 = 真实逐盘 waterfill 的同一「需求份额」量，无任何乐观外推；单测对拍一例。

物理解释：v3 的总账等价于「假设所有盘均匀受力」；TFS-D 在请求天然斜置（块集中在某盘）时自动把该盘的并发往回收、把余量让给落在冷盘的请求。若块分布均匀，两臂逐动作等价（frac≈1/3，每盘条件退化为总条件）。

### 2.3 物理设定攻击生成器（P 族）

| ID | 构造 | 打什么 |
|---|---|---|
| P1 热盘毒丸类 | 用 `disk_of` 直接搜索 h 值：找块落点集中单盘（frac_max 0.6~0.8）的类作为重读类；其簇到达 + 紧期限 | v3 的总账对热盘超载视而不见（总带宽没满、单盘爆了） |
| P2 背景流量窗 | b_schedule 在重读簇到达窗内把带宽压低（时间对齐）；报价 5ms 一份，v3 的 cap 中位数有 45ms 滞后 | 报价滞后窗内的错峰误放 |
| P3 热盘+冷盘混合 | P1 重类（热盘 1）+ 分散落点的轻读类 + 零读类 | TFS-D 应让冷盘轻读先行、v3 无差别 |
| P4 三盘对齐簇 | 三个 P1 类分别热不同盘，簇对齐到达 | 全盘同时热——检验 TFS-D 在无冷盘可让时是否与 v3 同化（必要性边界） |

场景：`alloc=max_min_disk`（3 盘 × 40），其余物理同第一轮（32 worker、batch=1、L=8）。

### 2.4 判定（预注册，双向）

- **H-A1（「需要存储状态」成立）**：存在 P 族敌意参数（3 seed 复核 ≥2 票），TFS-D 总 SLO ≥ v3 + 5pp **且** v3 在同格被击杀（对四臂最优差 ≥5pp）。→ 结论：当前总账视图不足，盘级状态应入报价。
- **H-A2（「不需要」成立）**：全部 P 族（含 h 搜索找到的最倾斜类、最强背景窗）上 v3 无确认击杀 **且** TFS-D 无任何格 ≥5pp 优势。→ 结论：在本模型内，总量视图对盘拓扑已充分（v3 的稳态即够用）。
- **中间态**：如实记录为「部分必要」（哪些子域需要、幅度多少），不硬凑二元结论。

### 2.5 冒烟区分度检查（AGENTS §5）

开跑前单格冒烟：P1 最倾斜类 + 满簇，确认（a）热盘确实被打满（逐盘利用率可从引擎侧核）；（b）四臂不全在天花板也不全崩；（c）TFS-D 与 v3 的行为确实出现分叉（决策序列 diff 非空）。任一不满足先调参数再开全量。

## 3. 线 B：两层必要性

### 3.1 参考引擎分辨力实验（adv/two_layer 内可答的部分）

**判据（预注册）**：存在敌意族（3 seed 复核）使「单层下放臂」对「两层臂」差 ≥5pp **且**两层臂不劣于直接提交臂 2pp 以上 → 层间分工有实证收益（在该语义下）。反向：全族两层臂与单层下放臂差 <2pp → 参考引擎分辨不出层间价值（结论移交 DV 侧，如实声明）。

生成器（B 族，均两层世界）：

| ID | 构造 | 打什么 |
|---|---|---|
| B1 保守代价放大 | 重读占比 0.5~0.7 × 到达率 60~90/s × 批上限 4~8 网格（第一轮 G13 的参数域细化） | 单层 issued 账本的中央等待；两层 active 账本的对照优势 |
| B2 加载位让位 | 慢加载重流（V 大）+ 紧期限小簇同实例 | 两层 E2 加载上限对小簇的保护；单层无此机制 |
| B3 反压边缘 | 重流簇 + 中等零读流（深度贴反压阈） | 已修的加载位反压在边缘参数下的剩余窗口 |

### 3.2 DV 侧规格（外部执行，本仓库只交付规格）

独立小文档 `docs/DV实验规格-TFS两层必要性-20261026.md`：五臂（直接提交/单层下放/两层 G-only/两层 E-only/两层全配）× 到达率 × 重读占比 × max_num_seqs，指标（总 SLO/分类 TTFT/中央等待/issued−active 时序），预注册假设 H1~H4（沿用 `docs/TFS工况边界与两层拆分设计-20261023.md` §5 并加必要性判据）。**参考引擎无论结果如何都不能替代 DV 结论**——此边界在结果文档中显式声明。

## 5. 风险与边界

- TFS-D 的每盘账本是「份额×条数」口径的一阶近似，不含逐盘 waterfill 的动态均衡——若 H-A1 成立，收益数字是下界（真实感知臂还可做每盘唤醒与剩余字节口径）。
- P 族的 h 搜索受哈希函数性质限制（HRW 的倾斜上限）；若搜不到 frac_max >0.6 的类，如实记录并用三盘非对称混合逼近。
- 参考引擎的 B 族结论只覆盖其能模拟的现象（下发≠开读、准入节奏、反压）；批内 token 预算等 DV 真语义不在内。
- 母工况锚点（E26f 负载、fcfs 分配）上 TFS-D 必须与 v3 等价或更优——否则盘感知臂本身不成立。
