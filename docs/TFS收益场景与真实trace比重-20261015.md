## 1. TFS 收益的场景(条件清单)

TFS 的收益不是无条件常数,而是四个条件的交集(`docs/TFS规则式调度器-20261014.md` §2.1,证据见 E26 系列):

| 场景 | 判定条件(可观测量) | 收益来源 | 缺失时的后果 |
|---|---|---|---|
| **S1 带宽分诊区**(大门) | 逐窗口到达读取速率 > 带宽供给 B(即 ρ→1);重流聚合需求超供给 | 错峰(配额 C)+守门 | 配额不 binding,收益归零 |
| **S2 簇到达** | 50ms~1s 窗口内同刻多条重流(峰/均值≫1) | 簇内节律(配额释放节奏) | 无簇则错峰无对象 |
| **S3 轻重异构** | 读取压力 d=V/c 分布分散(P75/P25、CV 大);零读/近轻流存在 | 填空(轻/零流恒可派) | d 全同时分诊无信息 |
| **S4 轻度计算饱和** | 窗口计算需求逼近 NPU 数 | 守门防排队死 | 计算极松时无害无益 |

另有一个**部署参数**:期限结构 α(期限有松紧,slack 排序才有分辨力)。

**结构条件(S2/S3/S4)决定"收益的上限形状",大门条件(S1)决定"收益是否兑现"**——S1 不成立时 TFS 退化为带老化保护的 slack-EDF,无害但无益(E27 连续工况教训)。

### 2.2 读法与结论

**结论一(比重的主答案):原始节奏下,收益场景的"大门"几乎不开。**
四份 trace 的临界带宽 B\*≤5.1 GB/s,比任何现实供给(E23 用 80、E26 用 120 GB/s)低 1.5~2 个数量级;B≥60 时窗口超订占比全部为 0.0%,B=30 时至多 1.0% 窗口 / 2.1% 请求(synthetic)。**按时间窗口计,分诊区占比≈0%;这就是为什么 E23 的实验设计必须按 ρ 定标回放**(其 rho_list={0.6,0.9})——原始 trace 太轻,直接回放测不出调度差异。

**结论二:但收益场景的"结构前提"在真实 trace 中大量存在。**
- S3 异构:四份全部强(d 的 CV 1.9~5.0)。synthetic 有 55.4% 零读请求;conversation 近轻流 42.2%、重流集中 72.7% 的读取量——轻重混排是常态,不是构造。
- S2 簇:Mooncake 两份生产 trace 高度成簇——87.5%/99.8% 的请求落在 ≥8 条/50ms 的簇内(1s 峰/均 = 28/3.4 与 47/6.7);synthetic 与 AgentX 样本无簇。
- 结论:**"门没开,但钥匙都插在锁上"**——一旦供给收紧或负载上升,S1 打开后 S2/S3 立即兑现收益。

**结论三:开门的两个杠杆(比重是部署量,不是 trace 内在属性)。**
1. **收紧供给**:B 降到窗口峰速率(31~43 GB/s)以下才出现超订窗口;B≥60 全关。存储侧供给充足的生产系统(如本地 NVMe 多盘)天然在区外。
2. **加压回放(E23 方法论)**:B=80 下,conversation 需加速 40×、toolagent 19×、synthetic 16× 才到 ρ=1。E23 的 ρ∈{0.6,0.9} 定标回放正是把 trace 推入开门区做实验——**在该口径下,分诊区占比=回放 ρ 的函数,可任意设定**。

**AgentX 专项观察**:样本(2 会话 231 请求)会话跨天、节奏极稀疏;但单请求上下文巨大(63K token 级,V_total 达 GB 级/条),活跃期窗口峰速率 51.5(overlap)~100.2(sequential)GB/s——**并发数低时瓶颈在单请求时延而非争抢**(B=30 的 32.9% 请求超订占比在"同窗≥2 条"净口径下降为 0%)。AgentX 的分诊区评估需要全量 393 会话的并发回放,当前样本不足(见局限)。

## 3. 判定路径(换 case 时的操作)

1. 算全体排队请求的 d 分布:CV<0.5 或 P75/P25<2 时,S3 无信息,收益上限≈0。
2. 估重流聚合需求:窗口到达读取速率(或 λ·E[V])对 B 之比 ρ:ρ<0.7 时大门不开,S1 无收益。
3. 看 S2/S4:有簇、期限有松紧则结构齐备;ρ≥0.7 时进入分诊区,TFS 预期捕获 MPC 收益的九成(E26f 实测 95%/91%,仅在该工况验证)。
4. TFS 单次运行以秒计:直接与 fcfs 同 case 对跑,即得该 case 的真实收益。

## 4. 局限

- **命中口径不可互推**(AGENTS §9):Mooncake 用首现命中(全局重复内容只计首次),AgentX 用理想前缀命中(会话内前缀全计);两者的 d 分布与 B\* 语义不同,表内数字不跨口径比较。
- AgentX 样本仅 2 会话 231 请求;时间戳为会话内相对时间,窗口指标给 overlap/sequential 两种叠放下界与上界;结论"节奏稀疏"对样本成立,对全量 393 会话未确认。
- 窗口超订是上界代理(未建模排队动态与服务重叠);"净口径"(同窗≥2 条)已剔除单大请求假阳性,但仍是到达侧口径,不等于在跑并发超订。
- c/V 由默认画像外推(L=32、κ=4.096e-6 GB/token/层、E23 同参);换真实引擎画像后 B\* 与 d 分位数需复算。
- 未扫 λ/α/批调度(n_max>1);S4 计算饱和仅在原始节奏下测得"远未饱和",加压回放后的计算需求由 ρ 与画像共同决定。
- 本分析为静态测量,不含仿真验证;"TFS 在 ρ≥0.7 的 trace 回放下捕获九成收益"的预期来自 E26f(合成负载),trace 回放下未验证。
