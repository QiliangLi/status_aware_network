## 1. 问题定义

前两次 E26f 运行的存储都是**聚合总带宽池**：母实验 FCFS 分配、重跑 max_min 分配，带宽都直接以 B(t)=120 GB/s 的单一池出现。真实系统（与主线 `SharedKVStorage` 的模型一致）中：

1. **总带宽来自各盘**：120 GB/s = 3 盘 × 40 GB/s，每盘独立容量；
2. **KVCache block 按一致性哈希落在唯一的盘上**（HRW；块对所有路径可见、无盘间冗余）；
3. 一次读取的块散在多块盘上，**完成由最慢盘决定**（哈希倾斜长尾）；
4. 盘内分配是逐块 IO 的 max-min（每块携带需求），不是流级聚合。

本实验回答四个问题：

- **Q1 稳健性**：加上盘拓扑后，E26f 的调度结论（五臂排序、mpcS−FCFS 差距、零读类二象性、TFS 捕获率）是否保持？
- **Q2 长尾的类签名**：块数少的类受哈希倾斜伤害更大（B 类每层 ~19 块 vs A 类 ~84 块）——B 的层读变慢/方差增大是否可观测？对 B-SLO 的边界余量（当前 100% 满格）啃掉多少？
- **Q3 盘间不均**：每盘利用率曲线是否显著分离（哈希倾斜 + 到达随机性 + 错峰策略的盘间印记）？总带宽利用率与单池 max_min 是否接近（功守恒预期）？
- **Q4 推演成本**：分配主体从流变成 (流,盘) 组，事件数约 ×盘数——MPC 成本相对单池 max_min（已降 1.3~2.1×）回升多少？

## 2. 存储模型形式化（cq 线移植）

### 2.1 放置（决定每个请求的 Block 从哪块盘读）

- **块定义**：`block_tokens`（默认 **512**，对齐主线与 Mooncake 口径）个 token 的前缀切片；层 ℓ 的读取量 = 该前缀层 ℓ 的 KV，即每层每块 `κ × block_tokens` GB（κ=4096e-6 GB/token/层，现行画像参数）。
- **放置函数（HRW，与主线同构）**：
  ```
  disk(prefix_id, idx) = argmax_{d ∈ [0, disks)} sha256(f"{pool}:{prefix_id}:{idx}:{d}")
  ```
  确定性、无随机数（CRN 不受影响）；增删盘只重映射少数块；**与层无关**（同一块各层同盘）。
- **prefix_id**：合成负载用 `"{class_id}:{h_tokens}"`（同类同 h → 同计划，E26f 每类恰一个计划）；trace 负载（后续）用 `"{source_file}:{source_line}"`。公开确定性信息，任何策略/推演可重建。
- **计划**：层读分解为每盘组 `((disk, n_blocks_d, bytes_d), ...)`，`n_b = ceil(h/block_tokens)`（末块部分字节，如 A 类 42883 = 83×512+407）。**C 类 h=0 → 无流无块**，零读语义不变。
- **块数账**：A 84 块/层、B 19 块/层、C 0——B 的最慢盘期望占比约 0.4+（19 块/3 盘的多项式倾斜），A 约 0.36；具体常量由实现时的单测锁定并写进结果文档。

### 2.2 需求与每盘分配

- **逐块需求 = q / n_b**（聚合需求守恒）：层 ℓ+1 流的 q = V/c 恰等于 Σ块 ×(块字节/c)，故逐块需求 = 块字节/c = q/n_b **恒等成立**；层 0 流（q=q_max）与到期提升（q→q_max）按同式按比例继承——聚合申请语义在块粒度下逐字保持。
- **每盘独立 waterfill**：盘 d 的就绪组内按块数展开（组内 K_d 块 = K_d 个同需求 claimant），`waterfill(cap_d(t), [q/n_b × K_d 展开])`，组速率 = K_d × 单块分配。跨盘不做任何再平衡（无跨盘副本/迁移，见 §10）。
- **盘容量**：`cap_d(t) = B(t) / disks`（池级带宽平摊，与主线公式一致；E26f B 恒 120 → 每盘恒 40）。
- **盘数派生（沿用四次修订的参数化）**：`disks = max(1, ceil(B / disk_bps))`，`disk_bps = 40 GB/s` 缺省 → B=120 自动 3 盘。**没有 disks 配置项**；总带宽是主配置。
- **独占/均匀退化性质**（单测锚点）：单流独占一盘时聚合速率 = 全盘容量；同类同质流每盘公平份额聚合 = B/N，与单池 max_min 在期望上重合（差异只来自倾斜与逐块公平，正是要测的对象）。

### 2.3 完成、事件与升速

- **流完成 = 其全部盘组完成**（最慢盘决定）：`read_ready[layer]` 在最慢盘组完成时刻写入。
- **组完成是重配事件**：某盘上先完成的组立即触发该盘 waterfill 重算（在途重配下沉到组粒度）；引擎 `_next_event`/完成处理扩展为组级。
- **boost_due 不变**：到期未读完的流 q→q_max，逐块需求按 q/n_b 同比例抬升后重配。
- **记账口径不变**：`integrated/actual/requested` 积分、flow 级账本与 `PublicFlow`（V/served/completed）保持流粒度——策略与指标的外壁不破。

### 2.4 与前两模型的对照

| | 母实验（FCFS） | max_min 重跑（单池） | 本设计（盘维度） |
|---|---|---|---|
| 带宽来源 | 聚合池 B(t) | 聚合池 B(t) | **每盘 B(t)/disks** |
| 分配主体 | 流（submit_seq FCFS） | 流（waterfill over q） | **(流,盘) 组 × 块展开** |
| 需求 | q | q | q/n_b（逐块） |
| 完成语义 | 流 | 流 | **最慢盘组** |
| 放置 | 无 | 无 | **HRW 块→盘** |
| 长尾 | 无 | 无 | **有（哈希倾斜）** |

## 3. 信息边界与推演穿透

- **策略视野刻意不变**：策略仍见流级账本 + 聚合 B̂ 估计（quote/est_bw/P75/配额全不动）。盘计划是公开确定性函数（prefix_id 可重建），但**每盘利用率/盘间倾斜不进策略可观测集**——本实验隔离"物理保真度"这一层；盘感知调度（把盘倾斜放进 quote）是后续独立课题，本次不做（若 Q3 显示倾斜成为一阶问题，届时立项）。
- **推演同物理**：`WorldState.clone` 拷贝盘组状态；`build_forecast_engine` 重注入流时按 (prefix_id, h) 重建每盘组（V=κ·h 反解 h，公开）；MPC/local 的估计世界与真实世界同一分配器——健康审计（fb=0）为验收项。

## 4. 配置接口

`sim/cq/config.py::StorageConfig` 新增两个字段（frozen，Fraction 口径）：

```python
alloc: str = "fcfs"                 # fcfs | max_min | max_min_disk（新增第三值）
disk_bps_gbps: Fraction = Fraction(40)   # 单盘上限带宽（物理基元）

@property
def disks(self) -> int:             # 派生，非配置项
    B = max(v for _t, v in self.b_schedule)   # B(t) 非降场景取峰值口径，单测锁定
    return max(1, math.ceil(B / self.disk_bps_gbps))
```

- `alloc="max_min_disk"` 才启用盘模型；`fcfs`/`max_min` 忽略 `disk_bps`（**已跑两组结果逐位可复现**，回归锚不动）。
- `submit` 扩展：`submit(flow_id, batch_id, layer, t, V, q, due, prefix_id=None, h_tokens=0)`——max_min_disk 下 (prefix_id, h_tokens) 必填（缺省报错，防静默聚合）；批内多成员计划按成员拼接。
- `interval_log` 并行新增 `disk_interval_log`：`[(t0, t1, [rate_d0..rate_dn])]`，仅 max_min_disk 且 record_intervals 时记录（不改既有四元组形状，E25 工具零影响）。
- 实验入口：`E26F_ALLOC=max_min_disk` → 场景 `replace(storage=..., alloc="max_min_disk")`，输出目录 `results/cq/eval/e26f_max_min_disk/`（EXP_DIR_NAME 规则沿用），records 增 `disks/disk_bps` 与每盘统计字段。

### 5.1 "复用前两组结果"的语义澄清

复用的**不是盘信息**——母实验（FCFS 分配）与单池 max_min 两组本来就没有盘，它们作为三方对照中的**无盘侧对照臂**原样复用（records 与图均不重算、不补盘统计）：

- 三方可比的是**共有口径**：总/分类 SLO、TTFT、甘特形态、逐 NPU、总带宽时序、汇总条形——这些指标在三组运行中定义完全一致；
- **每盘图只存在于新臂**（数据源 `disk_interval_log` 只在新运行记录）——"新臂每盘曲线分离 vs 旧臂单条总线"正是盘拓扑效应的呈现方式，不需要旧臂有盘数据；
- 结果文档中的三方对照表/图基于三组 records 合并重绘（新文件），已入库的旧图一律不动。

## 6. 实验矩阵与假设

**矩阵**：与 E26f 完全同构——{D1fA_k16, D1fB_k16} × 6 臂（fcfs/edf/localS/mpcS/mpcT/tfs）× CRN 同 seed（cA rep0/1/2 + cB rep0），唯一变量 `alloc="max_min_disk"`（3 盘）。已跑两组作为**无盘侧对照臂**原样复用、不重跑（语义见 §5.1——它们没有盘数据，正是对照结构中"无盘"那一侧）。

**预注册假设**：

- **H1（稳健性）**：五臂排序与 mpcS−FCFS 差距（cA +30.8 / cB +45.3pp 为基准带）保持 ±5pp 内——预判依据：两类死因（排队超期、A 的期限挤压）都由派发主导，读速率的二阶变化不跨生死线。
- **H2（长尾类签名）**：B 类层读 p95 变长（最慢盘占比 ~0.4+，等效速率打折），B-SLO 从 100% 满格回落（mpc 臂预计 95~100%，fcfs 的 B 本就 96.7%/40.8% 变化小）；A 类（84 块）读时间几乎不变。C 类零块不受影响（C-SLO 形态不变）。
- **H3（盘间不均）**：每盘利用率曲线显著分离（盘间 CV > 0.15 的时间占比可观）；总带宽利用率与单池 max_min 之差 < 5pp（功守恒）；错峰臂（mpc/tfs）的盘曲线台阶比 fcfs 臂错开得更明显。
- **H4（推演成本）**：MPC 墙钟相对单池 max_min 回升 ~2~3×（事件 ×盘数），仍低于母实验 FCFS 分配水平；健康审计 fb=0。
- **H5（逐块公平签名）**：同盘上不同类的块 IO 完成时间被拉平——B 的层读在 A 在场时不再"小而快"（B 单独在盘时 vs 与 A 共盘时的完成时间比，从甘特/requests 可判）。

## 7. 单测与验收标准

1. **放置**：`disk_plan`（Fraction）计数和 = n_b、末块部分字节、确定性、增盘（disk_bps 40→60，3→2 盘）只重映射少数块；与主线 `sim/storage.py::disk_of` 同键同落点（跨线一致性对拍）。
2. **每盘分配**：逐块需求聚合守恒（Σ块需求 = q）；单流独占一盘聚合速率 = 全盘；均匀多流每盘份额聚合 = B/N；3:1 倾斜流的完成由 3 块盘解析决定（Fraction 精确对拍）。
3. **完成与事件**：组完成触发该盘重配（在途重配组粒度）；流完成 = 最慢盘组（构造跨盘不同时完成的小场景）；boost 后逐块需求同比例抬升。
4. **回归锚**：`alloc="max_min"` 与 `"fcfs"` 在新增字段存在时行为逐位不变（复跑一次既有 smoke 对照 records）；`max_min_disk` 缺 prefix/h 报错。
5. **推演穿透**：clone 保留盘组；forecast 重注入流的盘组与真实同构（小场景对拍 fb=0）。
6. **端到端**：全臂缩放冒烟（E26F_TOTAL=60）→ 区分度检查（至少一个格点上 max_min_disk 与 max_min 的分类 SLO 差 ≥ 2pp，或披露"无差异"这一结果本身）；全量 pytest 绿；`tools/cq_mpc_health.py` 全绿。

## 8. 成本与排程

单池 max_min 重跑实测：cA mpcS 35 min/seed、mpcT 43 min、local 6 min，全矩阵实际墙钟 ~4.2 h（两阶段两路并行）。盘维度只放大**存储侧**事件（流完成 → 最多 3 个盘组完成，约 ×3），计算层/到达事件不变；**每盘内部同质组的屏障式同刻完成保留**（max_min 的加速来源不丢，FCFS 时代的串行管道不回来）——引擎事件总量估 +70~100%、单决策成本 +60~100% → cA mpcS 预计 **60~70 min/seed**。总墙钟预计 **5~6 h**（cA0+cB 两路 → cA1+cA2 两路）；四路并行（MPC_PAR=3~4，超订阅 ~1.5×）可压到 **3~4 h**。兜底 `E26F_TOTAL` 缩放。（初版 10~14 h 系按母实验 FCFS 分配成本惯性外推，过度保守，20261021 用户质询触发复核修正。）

## 9. 范围排除与已知限制（如实记录）

1. **无跨盘再平衡**：块钉死在哈希落点的盘上，不建模副本/迁移/读改道——倾斜只能被承受（这正是要测量的对象）。
2. **同类共享计划**：E26f 合成负载每类一个 h → 每类全体请求同一盘分布，倾斜是**类常量**而非请求级随机（trace 负载下才是分布）——读 H2/H3 时记住这一点。
3. **策略不感知盘**（§3 刻意）：若 Q3 显示盘倾斜造成一阶损失，"盘感知调度"另立设计，本实验只负责把损失量化出来。
4. **B(t) 平摊到盘**：动态背景负载按池级平摊（与主线公式一致），不建模"背景流量也落在特定盘"。
5. **层 0 的 q_max 语义**按 q/n_b 按比例继承（聚合申请 200 不变，不解释为"每块 200"）——与单池口径可对照。

### A.4 已知坑位（本系列移植的实测教训）

- **穿透三处**：`WorldState.clone`（盘组状态逐字段拷贝）、`build_forecast_engine`（StorageConfig 新字段 + 重注入流按 V=κh 反解 h 重建盘组）、`e26f_third` 场景 replace——漏一处即推演与真实规则错配（max_min 移植时 clone/forecast 是两个实弹坑）；
- 引擎 submit 扩展的调用点有**两处**：`_dispatch`（层 0）与 `_start_layer`（层 ℓ+1），都要传 (prefix_id, h_tokens)；
- 逐块需求用 q/n_b 从**当前** q 现算（boost 到 q_max 后自动同比例抬升），不要在 submit 时冻结；
- 组完成是重配事件但**流完成才写 `read_ready`**——别把组完成当层读完成；
- 图文件名一律经 E26F_TAG 前缀（`cq_fig_e26f_max_min_disk_*`），严禁覆盖母实验/单池已入库图。

### A.5 判定纪律

H1~H5 如实判（含"无差异"这一结果本身）；区分度不达 2pp 时先查 goodput 天花板与每类 max_disk_frac 常量再下结论（AGENTS §5）；MPC 臂零 fallback、dev 计数非零方可称 MPC 生效（健康审计口径）。
