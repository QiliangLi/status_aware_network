# DV 实验规格：TFS 两层必要性验证（交付外部 DV 工具执行）

| 项目 | 约定 |
|---|---|
| 创建日 | 2026-10-26 |
| 性质 | 实验规格（本仓库不能执行；DV 工具 = 真实 Dynamo + vLLM 框架 + mock 计算，见 `docs/多级速率tfs对照-20261020.md` 的既有口径） |
| 目的 | 在真实框架语义下回答「两层拆分是否必要」——本仓库参考引擎（`adv/two_layer.py`）已给出必要性实证（B2：层间分工 +43pp），但批语义是近似；本规格是其真值检验 |

## 1. 臂（5 个）

| 臂 | 内容 | 对照意义 |
|---|---|---|
| A1 直接提交 | 到达即下发，引擎原生 | 下界基线 |
| A2 单层下放 | TFS 单层语义整体放 Dynamo 层（issued 账本 + 配额；引擎原生 waiting/组批） | 「不拆层」方案 |
| A3 两层全配 | TFS-G（active 账本+在途预算+加载位反压）× TFS-E（slack 序 waiting、每实例重流加载上限、就绪优先、每步上报） | 被测方案 |
| A4 G-only | 只 Dynamo 层改（active 账本+反压），引擎原生 | 拆层消融 |
| A5 E-only | Dynamo 用 A2 的 issued 账本，引擎层用 TFS-E 规则 | 拆层消融 |

## 2. 工况矩阵

1. **B2 复现（主）**：每实例周期性注入慢加载大读请求（V≈6 GB、宽松期限）+ 30~60ms 后紧期限小请求簇（k=4~8，α=2.0~3.0）。参数沿参考引擎命中的形态：慢加载条数 {2,3,4} × 簇 α 细网格（0.25 步长）× max_num_seqs {4,8}。
2. **B1 网格**：重读占比 {0.5,0.6,0.7} × 到达率 {60,75,90}/s × 批上限 {4,8}（对应速率对照网格的加压端）。
3. 沿用速率对照的固定 seed 展示 + 多 seed 中位数口径。

## 3. 指标

总 SLO、分类 SLO、分类 TTFT（mean/p95）、**中央等待**（重读请求的下发等待）、**实例 waiting 深度时序**、**issued−active 计数时序**（在途滞留）、每实例加载并发数时序、带宽曲线。

## 4. 预注册假设

| 假设 | 内容 | 判定 |
|---|---|---|
| H1（必要性主） | 存在 B2 参数格：A3 总 SLO ≥ A2 + 5pp 且 A3 ≥ A1 − 2pp | 参考引擎结论在真实框架复现 |
| H2（消融归因） | B2 命中格上 A5 − A2 ≥ 5pp（引擎层规则的独立贡献）且 A3 − A4 ≥ 2pp（G 侧修正的增量） | 收益归属两层各自 |
| H3（B1 反向） | B1 全网格 A3 − A2 < 2pp（无分离）则如实记录——保守代价形态在真实批语义下可能不兑现 | 负结果也入档 |
| H4（机制） | A2 的 issued−active 差随重读占比/到达率单调增；A3 的差有界（≤ 在途预算） | 账本机制在真框架可见 |

## 5. 边界与纪律

- 结果落本仓库时按外部报告体例（同 `docs/多级速率tfs对照-20261020.md` 引入方式）；判定只认预注册口径，中途不换。
- 冒烟先行（AGENTS §5）：单格确认无 goodput 天花板、瓶颈在存储/实例排队。
- 本规格不占用本仓库实验号。
