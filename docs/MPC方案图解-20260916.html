调度器只能决定三件事：哪些请求拼一批、哪个实例先领、要不要晚点领。 简单规则（FCFS / SPT / EDF）用一条排序键回答这三个问题；MPC 的思路不同—— 像下棋一样，把每个候选走法在脑子里推演到终局，再落子。

②一次决策的五步

每当"有空闲实例且队列非空"（到达/完成/报价更新等事件触发），MPC 执行：

0

先拿一个保底动作

基础策略 π = guarded EDF（带老化保护的最早截止优先）给出联合动作。它是参照系，也是兜底。

1

从观测重建预测世界

MPC 不能看内部真值，只能用可观测信息：最新带宽报价 bw_hat（之后恒值外推）、自己提交过的读取流账本（已传字节、完成确认）、已到达请求的 h/u/deadline。

预测带宽 B̂(t) ≡ bw_hat（常值）
2

生成候选动作

从队列挑 ≤32 个候选请求（到达最早 / T0 最短 / 截止最早 / 余量最小 四池轮询，最老请求必入），按三种顺序贪心填出 ≤24 个候选批；再逐空闲实例组合成联合动作，并加入等待候选：

wait ∈ now + {0.05, 0.1, 0.2}·C_ref
（C_ref = 已到达请求 T0 的中位数；
另加预测的读取完成时刻）
3

在副本上推演到排空并打分

每个候选动作落实到一个系统副本上，之后固定用 π 继续执行，直到当前所有已到达请求全部完成，得到每条请求的预测完成时间 F̂。用 θ 的词典序元组打分：

θ=M: (max F̂, ΣTTFT)
θ=S: (失败数, ΣTTFT)
θ=T: (ΣTTFT, 失败数)
θ=R: (Σ TTFT/T0, ΣTTFT)
4

门槛校验，只落第一步

最优候选的主目标必须严格优于基础动作（gate=0 时即严格小），否则回落到 π。无论推演多深，只落实第一个动作；推演中的未来计划只是估值。预算：2 ms CPU / 2 万事件，超了就用保底。

两个容易误解的点：① 推演用的 FCFS、层依赖、批屏障与真实引擎完全同规则，但跑在"预测状态"上（带宽恒值、无未来到达），所以估值可能错——这就是 gate 存在的原因； ② 等待不是预订请求：WAIT 只设一个唤醒时刻，请求仍留在中央队列，任何新事件都可提前重评。

④为什么实验里 MPC 常常和 EDF 一模一样

E25 全矩阵（7080 次运行）中，MPC 相对 EDF 的配对差在四个目标、全部因子线上都是 0.000。机制上有四个原因，每个都能在动画例子里找到影子：

原因解释
参照系太强基础动作 π = guarded EDF 在深队列下已接近时延最优；MPC 只有找到严格更好的首动作（gate=0）才偏离——多数时刻找不到。
组批没有收益可挖真实 trace 的批内新 token 远超计算饱和点（N≫N_sat），换批成员不省计算（G≈1），重排只剩同步损失的移动。
等待等不来东西同刻突发型 trace（如 Conversation 同刻组占 100%）里，等 0.05–0.2·C_ref 期间不会到达新请求；带宽充裕时（STALL≈0）也没有要保护的旧流。
预算有限2 ms / 2 万事件内只推演浅层（H=1）；候选评分大多与基础动作打平，平局不切换。

反过来，这四个条件也指出 MPC 什么时候会有增量：B=20 且峰值利用率打满（有旧流可保护）、 突发之间有空隙（等得来新请求）、短 token 负载（换批成员有计算收益）、更松的 gate 与更深的预算。 这些正是 E25 报告 §7 列出的下一批实验格点。

⑤公式速查（与实现一一对应）

评分：θ 的词典序元组（首项是主目标，其余只破平局）
θ=M: ( maxi F̂i , Σ TTFT )   θ=S: ( #{F̂i>deadlinei} , Σ TTFT )
θ=T: ( Σ TTFT , 失败数 )   θ=R: ( Σ TTFTi/T0i , Σ TTFT )   越小越好；F̂ 为推演排空的预测完成时刻

对应 sim/cq/search.py: score_of()。注意 M 不能用"最大提前量"替代，S 是阶跃目标（救回 10.1→10 的请求才算数）。

候选批的三种排序（对每个锚请求 a 生成贪心批，保留每个中间不满批）
同形: |log1p hi − log1p ha| + |log1p ui − log1p ua
互补: |log ri + log ra − 2 log rref| ,  r = V/K（读算比）
紧迫: ( deadlinei, arrivali, ridi )

排序后逐项尝试加入，第一项违反硬约束（≤8 请求 / ≤token 上限 / ≤内存）即停批。候选预排序键 (−G_batch, min_slack, ΣV/ΣK, members) 取前 24。

等待候选与唤醒
wait ∈ now + {0.05, 0.1, 0.2} · C_ref  ∪  {预测读取完成时刻 ≤ now+0.2·C_ref}
C_ref = median{ T0i : 已到达 } （在线滚动，v1.4）

纯 WAIT 必须有严格未来的唤醒时刻；等待中的请求仍在中央队列，任何新事件都可提前重评。

门槛、预算与回退
切换条件: scorebest[0] < scorebase[0] − gate  (gate=0 ⇒ 严格改善)
预算: 2 ms CPU（软） · 20000 事件（硬） · 深度 H=1（E21/E23 eval 先例）
超预算/不可排空/状态失效 ⇒ 回落 π 并记账 fallback
预测状态的重建（信息边界）
带宽: B̂(t) ≡ bw_hat（最近一次报价，之后恒值）
流剩余: 以最近上报字节为锚，按预测服务扣减；完成确认强制清零
计算剩余: max(0, ĉ − 已进行时长)  （默认真值可见；误差模式对称施加）

推演引擎与真实引擎共用同一套 FCFS/层依赖代码，但输入是重建的估计状态——估错的后果由 gate 与回退兜住。
