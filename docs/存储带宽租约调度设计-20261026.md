## 0. 一页直读版

**系统**：请求到达路由器 → 立即转发到某实例 → 实例内排队、读数据（从多块盘）、算（layerwise：算第 ℓ 层时第 ℓ+1 层的读已在途）→ 按期限交付。每块盘带宽有接口可查的定值（例：30 GB/s）。

**四项技术，各管一件事**：

1. **轻重判定**（§2）：算一个数，决定这条请求"要不要走逐条申请的协议路径"。只管消息成本，不管排序。
2. **双信号路由**（§3）：轻读看算力信号选实例；重读看算力 + 囤积两个信号。保证不堆实例、不虚报算力。
3. **每盘放行规则**（§4）：一块盘一本账，正常路放行 + 有条件的例外路（允许被摊慢）+ 两条护栏。决定"这条重读现在能不能开读"。
4. **事件驱动记账协议**（§5）：账在"读开始"那一刻加、"末层读毕"那一刻减，全程贴合物理占用；租约带 TTL、周期对账兜底；实例内三条排队规则。

**一条重读的旅程**：路由器双信号选实例、立即转发（字段自带）→ 进实例等待队列（按宽裕程度排）→ 加载位前一位向账房预取 → 账房按每盘账本放行或压后 → 持租约开读、发"读开始" → 层式读算 → 末层读毕发"读毕"、账即刻减 → 进计算位。全程 4 条控制消息。轻读/零读：直接开读，0 条消息。

## 1. 系统设定与术语

**组件**：路由器（1 台，控制面）；推理实例 N 台（各 m 个计算位、若干加载位）；盘 D 块（各带宽定值，接口可查）；带宽账房（1 个控制面服务，持每盘账本、批重读）。

**请求字段**（路由器转发时自带，全部可从公开信息算出）：需求速率 d（=总读量 ÷ 独占完成时间）、每盘份额表（块→盘落点由公开确定性哈希定）、期限、轻重标记。

**三个常数**（例中以单盘 30 GB/s 代入）：

| 常数 | 定义 | 例值 | 依据 |
|---|---|---|---|
| 判定线 | 单盘带宽 × 1.1 | 33 | 10% 容差 = 对抗全程验证的安全余量 |
| 例外带 | 单盘带宽 × 1.5 | 45 | 允许的最大拉伸上限 |
| 轻重线 L | 单盘带宽 × 0.1 | 3 | 容差带同源（§2） |

**术语**：宽裕程度 = 期限 − 现在 − 自身剩余服务时间（越小越等不起）；在读 = 已持租约正在读取；等带宽 = 已下发、等账房批准；末层 = 最后一层（纯计算、不再读）；Δ = 紧迫窗口 ≈ P95(单请求服务时长)；S̄ = 重读平均服务时长（在线统计）。

## 2. 技术一：轻重判定

**解决什么问题**：真实协议里逐条申请有消息成本；需要一条线决定"谁付这个成本"。同时不能重蹈历史 75% 分位线的覆辙（依赖负载统计、可被污染、冷启动漂移——对抗一轮 G2/G5 击杀过）。

**规则**：

> 重读 ⇔ 该请求在其最热盘上的份额 max_d(d × 盘份额) > L = 单盘带宽 × 10%
> （30 GB/s 的盘上即 3 GB/s；60 GB/s 的盘自动变 6。）

**依据**：10% 是整套机制的安全余量——份额低于 L 的请求即使完全不控、误放一条，最多消耗一条余量，翻不出安全区；高于 L 的单条即可击穿，必须逐条管。线只由盘带宽和余量宽度两个系统常数决定，与负载无关（换负载、冷启动、恶意构造都不动）。

**角色边界（重要）**：标记**只决定协议路径**（重读=预取申请+租约+两条事件；轻读=直接读、只进周期聚合），**不参与任何排序**——所有请求的排队一律按宽裕程度。仿真侧事实：记账零开销时标签可整体删除（nolabel 实验：母工况逐位等价、全档案免疫、G2 悬崖形态消失）；真实协议里标签的存在理由是消息成本，不是调度逻辑。

**部署定线**（在线可测，运行时可调，正确性不依赖取值）：
- 检查一（消息预算）：实测超线占比 f，消息率 = 到达率 × f × 4 ≤ 预算，超则调高 L。
- 检查二（聚合误差）：L ≤ 容差带 ÷（单盘到达率 × 聚合周期）。例：50 条/s、5ms 周期 → L ≤ 12（默认 3 安全）；周期 50ms → L ≤ 1.2（缩周期或降 L）。

**边界**：需求速率含计算时间估计，误判恰发生在 L 附近，代价 ≤ 一条余量，被 10% 吸收。

## 3. 技术二：双信号路由

**解决什么问题**：只看算力会把等带宽的重读当成不存在（堆实例）或当成已占用（虚报算力、误路由）——两个方向都错（DV issued 口径实测：虚报代价随负载单调放大）。

**两个信号**（实例周期上报，互不混线）：

- **算力信号 A(i)** = 实例 i 在跑批请求的剩余计算时间之和 ÷ 计算位数 m(i)。
- **囤积信号 B(i)** = 实例 i 上等带宽批准的重读条数。

**三状态归属**（核心表）：

| 请求状态 | 进 A(i)？ | 进 B(i)？ | 理由 |
|---|---|---|---|
| 在算 | 计 | 不计 | 正在占用 |
| 在读（马上要算） | **计** | 不计 | 读时长已知、读毕即进算，预测窗口有界 |
| 等带宽（何时能算未知） | 不计（计入即虚报） | **计** | 开工时间未知，算"未来"不算"现在" |

**公式**：

> 轻读/零读：选 **argmin A(i)**（它们下发即开算，"已下发"≈"在算"，单信号即准）。
> 重读：选 **argmin [ A(i) + B(i) × S̄ ÷ m(i) ]**——囤积折算成同单位的"未来计算位时间"并入打分。
> 硬反压兜底：B(i) > 2 × 加载位数 → 该实例不接新重读。

**数字例子**：甲 A=0.30、B=3；乙 A=0.05、B=0；S̄=0.1s、m=4。重读打分：甲 0.30+3×0.1/4=0.375，乙 0.05 → 发乙。轻读只比 A → 发乙（乙满则回甲，甲的 B 不吓轻活）。

**关键事实**：盘跨实例共享——重读落在哪个实例读的都是同一块盘，实例选择不影响盘负载（全局节奏归账房）；路由排斥解决的是排队公平与算位填充，不是盘保护。

## 4. 技术三：每盘带宽账本与放行规则

**解决什么问题**：总带宽账看不见"总量没满、单盘已爆"（对抗二轮 P4：总账视角一类请求整类归零，每盘账 +58pp 全救）；硬上限又在临界组合过度拒收（P1：−12~−33pp）；一步期限算术看不见队里的同期限簇（feas 实验：1.000→0.667）。

**账本构成**（账房持有，每盘一本）：

> 账本[d] = Σ 在读重读份额（逐条精确，事件驱动） + 轻读聚合（周期估计）

紧迫未决（队里"再等必死"的重读份额）**不进账本加法**，只在例外路条件 (b) 使用（加法式会在波释放时刻错杀、白闲盘——见 §8 更正记录②）。

**放行规则（五步 + 护栏，按序）**——对候选重读 c（盘 d 份额 s_c）：

1. 正常路：账本[d] + 轻读聚合 + s_c ≤ 判定线（33）→ 放行。
2. 界外检查：新总额 Σ' ≤ 例外带（45）？超 → 拒、留队。
3. 拉伸系数 k = max(1, Σ' ÷ 容量)。
4. 条件 (a)（在跑者）：每条在读 i 满足「现在 + k×剩余读时间_i + 剩余计算_i ≤ 期限_i」？任一超 → 拒。
5. 条件 (b)（队内紧迫者）：每条紧迫 j（期限_j − 现在 − 服务_j < Δ）满足「放行后预计开读_j ≤ 期限_j − 服务_j」？任一被推过线 → 拒。
6. 全过 → 放行（例外路），账记 Σ'。

> **护栏（优先于一切）**：盘账为空 → 必放一条；盘有富余且队列非空 → 必放（防 NPU 饿死，可观测硬规则）。

全部输入为公开量（剩余读 = 剩余字节 ÷ 需求速率；剩余算 = 层数进度 × 每层算时）。

**例外路的正确收益解释（layerwise 修正后）**：算第 ℓ 层时第 ℓ+1 层的读已在途，单条请求自己就把盘喂到其需求速率——例外路买到的**不是**"填计算期盘空档"，而是**单条需求用不满盘的余量只能由下一条消费**。例（R：1 GB、需求 20 GB/s、8 层各 125MB/算 6.25ms）：单条独占完成 ≈56ms、盘平均利用率 ≈59%；例外放行第二条（各摊至 15 GB/s）完成 ≈75ms、利用率 ≈89%（末层空泡互填），尾部吞吐 +49%。盘产出守恒（≤30 GB/s），突破判定线改变的是"谁何时读"，不是带宽总量。

**数字走查**（t=50 账本刚清、R3 已放账 21）：候选 R4——① 21+20=41 ≤ 45 ✓；② k=41/30=1.37；③ R3：50+1.37×67+50≈192 ≤ 400 ✓，R4 同 ✓；④ 队内 R5~R7 最晚开读仍在 200ms 外 ✓；⑤ 放，账记 41。同时刻来 R5（61>45）→ 第②步拒。

## 5. 技术四：事件驱动记账协议与实例内规则

**解决什么问题**：记账若从"下发"起算，通信时间与实例排队时间全部变成账面虚占（用户纠偏，与 DV issued 口径同源）；释放若等"请求完成"，末层纯计算期被白记（对抗一轮 G4：批间空档致 0.572 对 0.921）。

**协议（重读四条消息）**：

1. **预取**：重读到加载位**前一位**时向账房发申请（往返与队尾等待重叠，不占关键路径）。
2. **租约**：账房准许时下发，含额度（每盘份额）与 TTL（预计读毕 + 余量）。压后 = 请求继续留在实例等待队列（**没有调度器排队**——现实栈路由即转发）。
3. **读开始事件**：实例真正开读那一刻发出——账本从此刻加。虚占窗口 = 准许到开读的一次消息延迟，且被预取重叠。
4. **末层读毕事件**：读完最后一块那一刻发出（不等计算完成）——账即刻减、位置立即让出。

**兜底**：TTL 到期自动回收（读毕消息丢失）；周期拿存储侧每盘**实际流量**对账（防漂移；记账口径必须与真实分配同构——E26f local 崩塌教训：模型失配被公平分配惩罚，73.1→48.6）。

**误差单侧性**：加（准许时刻，账房本地）精确；减（事件到达）偏保守——误差方向只会"多记少放"，不会塞爆。浪费上界 = 释放延迟 × 释放速率；敏感锚 5~10ms（G4 实测），事件驱动 0.1~1ms，低一个量级；10% 判定线容差再兜一层。

**实例内三条规则**（对抗二轮 B2：单层语义 57.1% vs 带保护 100%）：

1. 等待队列按宽裕程度排（与轻重标记无关）；
2. 同时在加载的重读数 ≤ 全局额度 ÷ 实例数（加载位上限）；
3. 数据已读完的请求优先进计算位（就绪优先——不让未就绪的重读挡住已就绪的轻读）。

**消息计数**：重读每条 4 条小消息（预取/准许/读开始/读毕），轻读零读 0 条逐条 + 每实例每周期 1 条聚合。λ=600/s、重读 1/3 时约 800 条/秒——远低于单点处理能力，且全部在等待路径之外。

## 6. 端到端走查（三幕，layerwise 修正后数字）

设定：盘0/盘1 各 30；甲/乙各 4 计算位。R（重读）：1 GB 全落盘0、需求 20 GB/s、8 层各读 125MB/算 6.25ms、期限到达+400ms。L（轻读）：0.05 GB 分散、每盘 ~0.5、读 5ms+算 45ms、期限 200ms。C（零读）：不读、算 40ms、期限 160ms。

**幕一（主流程）**：t=0 R1 到 → 路由器双信号选甲、立即转发 → 预取 → 账 0+20=20 ≤ 33 放 → 开读发事件、账 20。t=5 C1 到 → 直接进计算位。t=10 L1/L2 到 → 直接读（聚合 +1）。t=30 R2~R4 到：R2 走例外路（41 ≤ 45、k=1.37、(a)(b) 过）放、账 40；R3（61>45）拒留队。t=50 R1/R2 末层读毕 → 账即刻 40→~1 → R3 放、R4 例外放（41，条件过）、账 41；R1/R2 进计算位。C/L 全程无一条被重读挡。

**幕二（信号分路）**：t=55 快照——甲：R1/R2 在算、R3/R4 在读、R5~R7 等带宽；乙空。甲报（算力信号含在读的 R3/R4，囤积 3）。C8 到 → 只看算力 → 均衡路由（囤积不吓轻活）。R8 到 → A + B×S̄/m 打分 → 甲 0.375 vs 乙 0.05 → 发乙；乙的 R8 照样向盘0 账房申请（盘不认实例）。

**幕三（长尾）**：40 条 R 同刻到 + C 流 t=100 停。混跑期（t<100）：~2R 并读 + C 填满其余计算位，NPU 满（E26f 同构形态 +30~45pp）。尾部（t>100）：单条独占 56ms/59% 盘利用 vs 例外双条 75ms/89% → 尾部吞吐 +49%；NPU 忙位 ~3.5/8 = 物理上限（R 搬 1 GB 只换 50ms 计算，盘喂不出更快）。死 R 算术：窗口 350ms × 30 条/s ≈ 10~11 条能读完，其余 ~29 条任何调度救不活（到达 40 > 容量 12）——调度只挑救谁，造带宽归入口准入。

| 设计决定 | 依据 |

## 10. 验证状态与未决

**已验证（对抗口径）**：每盘账本 vs 总账（P4）；例外路两条件的各自必要性（P1/P4/feas 配对）；末层释放时机（G4）；实例内规则（B2）；信号口径教训（DV/local）。
**未验证**：五步放行规则的完整合成版；双信号路由公式；协议本身（预取/租约/TTL/对账的消息开销与失败路径）——均为第三轮对抗与 DV 工具的对象（DV 规格：`docs/DV实验规格-TFS两层必要性-20261026.md`，需按本终版增补租约臂）。
**已知边界**：例外带 1.5 与 Δ 是锚定常数非推导最优；纯重读尾部 NPU 忙位受物理上限约束（例中 ~3.5/8）；到达率超容量部分归入口准入非调度器。
