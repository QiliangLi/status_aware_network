TFS 方案图解 规则式带宽感知调度 · 流程图联动版

TFS（Triage-Fill-Stagger，cq_tfs）是把 MPC 的赢法写成死规矩得到的零推演调度器： 不建副本、不推演、不预测带宽，每个决定只做排序 + 计数，单次决策约 0.11 毫秒（MPC 约 3.5 秒）， 却拿到 MPC 相对 FCFS 收益的约九成（E26f 实测 95.3% / 91.3%）。 本页用一个可以手算的突发例子，逐步展示它的完整处理流程。
本页自足。看懂例子需要的全部背景在 §1 预备知识（60 秒读完）； 规矩从哪来的在 §2；§3 左边是完整流程图、右边是联动的例子—— 例子每前进一步，流程图高亮当前环节（点击流程图节点可跳转）； 长例子在 §4；与 FCFS 的对照在 §5；验证数字在 §6。

①预备知识：看懂例子需要的四个事实

1.1 三类请求，读取压力天差地别

每个请求 = 已缓存的前缀 h（要读回来）+ 新算部分 u（要真算），逐层执行：读一层 → 算一层。 把"每层要读的字节 ÷ 每层要算的时长"记作读取压力 d——它衡量这条请求对共享带宽的挤占强度：

A · 重读快算
每层读 175.6 MB每层算 6.0 ms
d = 29.2 GB/s期限 198.5 ms
B · 轻读慢算
每层读 38.5 MB每层算 28.6 ms
d = 1.35 GB/s期限 914.9 ms
C · 零读纯算
每层读 0 MB每层算 48.2 ms
d = 0 GB/s期限 192.7 ms
系统
32 个 NPU带宽上限 B = 120 GB/s
每批 1 条期限 = 4 × T0

1.2 手算钥匙

门槛 = 全体排队请求 d 的 P75（本例 16A+16B+16C → P75 = 29.2，恰好圈中 A 类）
配额 C = ⌊ 带宽 B ÷ 门槛 ⌋ = ⌊ 120 ÷ 29.2 ⌋ = 4 —— 同时最多 4 条 A 在跑
时间预算 slack = 期限 − 当前时刻 − 服务时长 T0（到达瞬间 = 3×T0）：
　C：3×48.2 = 144.5 ms ＜ A：3×49.6 = 148.9 ms ＜ B：3×228.7 = 686.2 ms
一条 A 的服务 ≈ 读 1.5 ms/层（与算重叠）+ 算 48.2 ms ≈ 49.7 ms

为什么 C 的期限反而比 A 短？C 不用读第一层，T0 更短（48.2 vs 49.6 ms），期限 = 4×T0 也就更紧。 这条"最急的病人恰好不占任何资源"是本例最有意思的地方。

②四条规矩从哪来（都有实验出处）

规矩内容出处（E26 系列）
R1 填空轻流与零读流永远可派——不占带宽配额，有空闲 NPU 就上E26f：C 类在 MPC/TFS 下 100% 活，在 FCFS 下只活 30%（纯排队死）
R2 守门重流并发 ≤ 配额 C；满员就跳过它继续往下找，不中断扫描E26e：MPC 每簇只放 ≤5 条 vs FCFS 一口气 16 条，A 存活 20% vs 7.5%
R3 错峰等待无可派时 WAIT 到最早在跑重批的完成时刻——用确定的事实，不用预测E26f：MPC 需求超订 75% ＜ 实际饱和 86% = 压平了扎堆申请
R4 反单维排序排队按时间预算（谁先耗尽谁先），宽预算让位；老请求保底但不越过在等的轻流E26f：纯期限序的 EDF 把 B 饿死（28%）；纯到达序的 FCFS 在计算饱和下把 B 排队死（40%）

一句话：MPC 两小时推演换来的动作，与这四条规矩的输出重合度超过九成 （MPC 对其基础策略的有效偏离不足 2%，且集中在洪峰时刻）——规矩比想象中值钱，剩下的才是"看远"的溢价。

⑤和 FCFS 正面对比：同一瞬发，两种命运

关键差别在t=0 这一瞬间的派发选择。FCFS 按到达序把 16 条 A 一起放出去； TFS 只放 4 条（=配额），把不占带宽的 C 全部塞满、轻读的 B 补位：

4.1 瞬时带宽需求（16 条 A 齐发 vs 4 条 A 错峰）

FCFS：16 条 A 同时在跑467 GB/s
16 × 29.2 = 467 ≫ 120（超订 3.9 倍）
TFS：4 条 A + 12 B + 16 C132.9 GB/s
重流 4×29.2 = 116.7 被配额钉住；轻流 12×1.35 = 16.2 随意

超订不产生额外吞吐——带宽物理上限就是 120。16 条 A 齐发的结果是全体 A 的读取排队变长、 算力空转等数据（IO 等待海），紧期限的 A 和 C 反而成批死亡。

4.2 结局对照（E26f 存储瓶颈格点 D1fA，3 seed 中位数）

读法：TFS 用 FCFS 的成本拿到接近 MPC 的成绩——差距 1.4pp；计算瓶颈格点（D1fB）上 TFS 72.2% vs MPC 76.1% vs FCFS 31.4%。EDF 的教训值得一看：它优先救期限最短的 C（45.8%），却把宽期限的 B 活活饿死（28.3%）——单维排序在三类混合下必崩，这正是 R4 存在的原因。

⑥验证数字（全部来自已入库的实验记录）

收益捕获：TFS 总 SLO − FCFS = 71.7 − 43.6 = 28.1pp；MPC − FCFS = 29.5pp → 捕获 95.3%（存储瓶颈格点）。 计算瓶颈格点：40.8 ÷ 44.7 = 91.3%。
成本：单次决策纯耗时 0.11 ms（计时包装三次取中位）vs MPC 均摊 3529 ms——便宜约 3 万倍； 端到端墙钟 6.9 s vs 6896 s。
不变量单测：8 项全过（配额守恒、16A+16B+16C 突发形态恰为 C×16+A×4+B×12、slack 序、锚点让位、 确定性、纯 C 排空解析吻合、单类重流与 MPC 基座逐动作等价）。

边界：这些规矩蒸馏自"带宽有争抢、读取压力异构、期限有松紧"的工况（分诊区）。 带宽充裕时配额自动不生效，TFS 退化为带保底的排序派发，无害但也无增益； 深度计算饱和与多请求合批（batch>1）不在已验证范围。
