## 1. 问题定义（实证根因，非猜测）

E26 §4.7 在决策快照上逐关卡检验，定位两个**结构性**根因：

**P1 候选生成是"排序前缀"式，构造不出"资源组合"式动作（联合决策点）**
`_joint_actions` 逐 worker 扩展、每层截断 J_width=16、批排序按 (−G, 期限)——32 worker 的联合动作里只剩"按同一排名表取前若干名"的 EDF 形前缀；"4A+27B"这类跨层组合在第 5 层截断即死。实测（D2 t=0 突发，评分预算 30 万）：基础动作（全 32A）θ=S 评分 (32 fails, 57.77)，**4A+27B=(23, 40.68)、3A+28B=(23, 40.34)——评分器与目标（θ=S/θ=T 皆然）都认账，但该候选从未被生成**。注入后 MPC 仅凭 2 次联合点偏离即 66.7%→76~77%；类无关的 Σ(V/c) 配额组合器也有 66.7%→70.8%（偏离 73/36 次，`tools/e26_quota_unlock.py`）。

**P2 稳态信用分配——单 worker 决策点一步动作边际价值≈0（深队列稳态）**
深队列（3840 D1 ρ1.0，队列 121、1 个空闲 worker）快照实测：派 A/派 B/4A/3A 四种动作的推演评分**逐位相同**（θ=S=(143, 148.2696)；θ=T 同）。错峰的 +31pp（stagger4=73.6% vs FCFS 42.4%）是"上千个决策持续压并发"的轨迹级收益，单个决策只分到 ~0.006s 的 TTFT 差——H=1 + GuardedEDF 延续的结构下永远过不了"严格改善"门控。θ 换成 T 无济于事（同打平）。

**推论**：这不是 bug 而是实现与目的的错配——MPC 的目的（靠搜索找到好动作）要求候选空间覆盖"资源组合形"动作、且评分能感知轨迹级收益；当前实现两者皆缺。修正必须同时动**候选生成**与**延续基线**。

**设计试点教训（20260929 晚，朴素配额控制器失败）**：把 Σ(V/c)≤B 的配额装包直接做成常驻策略（BW-EDF）是坏的——B 类涓流（d≈1.35）几乎免费却被一刀切挡住（4A 后仅容 3B，25 worker 进 WAIT 空转、引擎在 20ms 唤醒上爬行，单 run 超 1 小时不收敛）。教训：**聚合口径必须按"重需求边际"计费**（重流 d≥阈值才计入配额；轻流免费），且 WAIT 唤醒要对齐"下一读取完成"而非固定短间隔。stagger4（=对 d≈29.18 的重流限并发 4）正是该口径的离散特例，r1.0 实测 73.6% 证明方向正确。

## 2. 设计目标与非目标

**目标**
1. 联合决策点：候选集覆盖资源组合形动作（类无关、mooncake 连续分布适用、无手工 A/B 先验）；
2. 稳态决策点：一步偏离的边际价值非零（带宽感知延续），且**搜索失败时的兜底动作本身就是带宽感知的**（MPC 的地板抬升）；
3. 全程只用公开信息（信息边界不变）；搜索成本不高于现状（事件预算口径不动）；
4. 可消融：候选生成与延续各自独立开关，收益可归因；
5. 健康监测覆盖新路径（n_deviate/n_searched 等照常落盘）。

**非目标（本期不做）**
- 真·多步规划（H>1 的逐决策点分支实现）——P2 的彻底解法之一，但成本高，列为二期；
- 学习式/自适应配额（在线调参）——一期用固定网格 + 网格内搜索；
- 更换 θ 目标语义（mpc_T 口径不变）。

## 3. 方案总览

三处修改（M1 必做，M2 必做，M3 观测）：

```
M1 组合式候选生成（治 P1，联合点）
   build_batches/_joint_actions 增加"资源感知组合器"：按期限序贪心装包，
   重需求边际计费（d_i = V_i/c_i ≥ d_heavy 才计入），配额网格 Q 网格化，
   产出 ≤|Q| 个组合形联合候选，排评分队列最前（预算优先）。

M2 带宽感知延续与兜底（治 P2，全部决策点）
   MPCPolicy 的 π 从 GuardedEDF 换成 GuardedEDF-BW（期限序 + 重需求并发
   上限 + 老化保护 + WAIT 对齐下一读取完成）。作用面：
   a) 兜底动作（搜索放弃时）= 带宽感知 → MPC 地板抬升（≥ stagger4 水平）；
   b) 推演延续 = 带宽感知 → 单步偏离在"错峰化的未来"里评估，边际非零；
   c) est 世界的闭环 π 同步替换。

M3 门控观测（治 P2 的可诊断性）
   记录 n_tie（候选与基础动作主目标打平的次数）与 n_near（次目标改善
   幅度分布），不改门控语义；为二期（多步/容忍门控）提供数据。
```

**为什么 M2 是治 P2 的正确一期方案**：P2 的本质是"延续策略把错峰抹平"。把延续换成带宽感知后，评分器看到的未来本身就是错峰的——不需要 MPC 表达"持续压制"，只需要它在错峰基线上做局部改良。stagger4 的 73.6%（r1.0）即该基线的下界实证（M2 的兜底策略至少是它）。

## 4. 详细设计

### 4.1 GuardedEDF-BW（M2 的 π）

排序键、老化锚点、填批语义全部继承 GuardedEDF；仅增加一个**决策期构造的能力检查**（feasibility extra）：

```
decide(snap, scn):
  d[i] = V_i/c_i            # 公开量：κh 与 c_hat（预测器同源），连续分布通用
  heavy(i) = d[i] >= d_heavy
  在跑重需求数 H_run = Σ heavy(pw.members)（对多成员批按批聚合 d_batch 判重）
  extra(members) = (H_run + H_chosen + Σ heavy(成员) <= C) or 老化锚点豁免
  其余与 SimplePolicy.decide 相同（期限序 + fill_batch_checked(extra)）
```

参数：`C`（重需求并发上限，默认 = ⌊B/d_heavy⌋ 自适应）、`d_heavy`（重流阈值，默认取已到达请求 d 分布的 P75——分位数口径类无关，mooncake 适用）。**无需手工 A/B 标签**：E26 里 P75 恰好把 29.18 划为重、1.35 划为轻，退化为 stagger(C≈4)；mooncake 下自动落在连续分布的头部重流。

WAIT 语义：配额满时不派发、唤醒时刻 = max(now+ε, 最早在跑流的完成时刻)（对齐物理事件，杜绝 20ms 空转——试点教训）。

老化保护：保留 GuardedEDF 的 W_guard 锚点豁免（防饿死），锚点请求无视配额强制进入。

### 4.2 资源感知组合器（M1）

在 `_joint_actions` 入口、标准逐 worker 枚举**之前**生成组合候选：

```
compose(node_snap, scn, quota 网格 Q):
  ordered = 队列按 (deadline, arrival, rid)
  for C in Q:                    # 重需求并发网格，如 {2,4,8} 或 {⌊B/d̄⌋ 邻域}
    acc_heavy = 在跑重数；acts=[]
    for r in ordered（逐条贪心，重数超 C 则跳过重条、试下一条轻条）:
        装 worker；装不下（重超限）→ 跳过；轻条恒可装
    未获派发的 worker → WAIT(对齐下一读取完成)
  return [组合动作×|Q|]           # 评分顺序：组合候选 → π 动作 → 前缀窗候选
```

- 候选数 ≤ |Q|（默认 3），每个仍走标准 forecast_drain 评分；**事件预算 2 万/决策不动**——组合候选排在队首，保证深积压时（基础推演吃预算）它们最先被评。
- 信息边界：只用 node_snap（队列形状、worker 占用）+ 公开公式（V=κh、c_hat、d=V/c），与现有候选一致。
- 网格 Q 的取法：以 ⌊B/d_P75⌋ 为中心 ±1 档（一期固定；二期可在线分位数）。

### 4.3 MPCPolicy 接口与口径

```python
MPCPolicy(pid, local, H=1, theta, c_ref, budget_s,
          max_events=20000,
          base="bw_edf" | "edf",       # M2 开关（默认 bw_edf；"edf"=旧口径）
          composer=True | False,       # M1 开关（默认 True）
          bw_params={d_heavy_p75, C_grid, wait_align})
```

- `base="edf", composer=False` = 与现行逐位等价的**旧口径**（回归锚点）；
- local 消融沿用 local=True 评分口径不变（其 π/兜底同样切到 bw_edf——local 与 mpc 的唯一区别仍只是评分带宽口径，公平可比）；
- 记录字段：records 增 `mpc_base`、`mpc_composer`、`n_tie`、`n_near_p50/p95`、`d_heavy`、`C_grid`；`code_rev="mpc-v2-20260929"`；健康审计 `tools/cq_mpc_health.py` 消费同一组字段。

### 4.4 成本

- 组合器：每联合决策 O(K log K)（排序复用），可忽略；
- BW-EDF 的 decide：与 GuardedEDF 同阶（多一次 d 查表，预计算 dict）；
- 推演成本不变（预算封顶）。预计全量 run 墙钟与 E26 现状同量级（240 规模 mpc 单 run 分钟级；3840 深队列 1.5~4h）。

## 7. 实验设计与验收标准

**冒烟（1 格点 ×4 口径）**：240 D2_b1.0_a4，{(edf,F), (edf,T), (bw_edf,F), (bw_edf,T)}。
门槛：守恒零失败；n_fallback=0；(bw_edf,*) 的 n_deviate>0 或兜底已错峰（并发 A p90 ≤ 8）；mpc 单 run ≤ 40 分钟。

**全量 A：E26 240 矩阵重跑（mpc/local 8 格点 ×2α，θ=S）**，4 口径消融在代表格点（D2_b1.0/b0.75、D1_r1.1）上做。

| 判据 | 门槛 | 依据 |
|---|---|---|
| A1 联合点解锁 | (bw_edf,T) 在 D2 α4 ≥ 70.8%（≥ 配额注入实测）且 n_deviate>0 | §4.7 通用组合器 +4.1pp |
| A2 地板抬升 | (bw_edf,F) 兜底水平 ≥ 71.8%（stagger3 实测）@240 D2；≥ stagger4 的 75% 方向 | 重需求上限=stagger 的一般化 |
| A3 不回退 | 全部格点 mpc-v2 ≥ 旧口径（66.7%） | 修复只增不减 |
| A4 健康审计 | cq_mpc_health.py 无 DEGRADED；零偏离格点显式披露 | 监测机制 |

**全量 B：3840 D1 深队列验证（ρ1.0/ρ1.1，α4，mpc-v2 θ=S）**——P2 的真考场：

| 判据 | 门槛 |
|---|---|
| B1 vs 基线 | mpc-v2 ≥ FCFS（42.4%/13.8%）——**硬门槛**（大纲 §7.1 首次达成） |
| B2 vs 已知最优形态 | mpc-v2 ≥ 73.6%@ρ1.0（≥ stagger4），目标 75%+ |
| B3 机制证据 | 甘特呈错峰形态（IO 等 ≤ 6% vs EDF 11.6%，图 3 口径）；并发 A p90 ≤ 5 |

**全量 C：E25 污染刷新抽样**：conversation/toolagent w9 OL ρ0.6 α4（±B80），mpc-v2 vs 修复后旧口径（71.3% 锚点）——量化 M1/M2 在**组批工况**（mooncake）的增益与不回退；d_heavy 分位数在 mooncake 上的落点报告。

**执行顺序**：实现+单测 → 冒烟 → 全量 A → 全量 B（后台 2×~2-4h）→ 全量 C → 结果文档（嵌图：错峰甘特对比、消融表、健康审计输出）。

## 8. 风险与缓解

| 风险 | 缓解 |
|---|---|
| d_heavy 分位数在极端混合分布下不稳定 | P75 仅为初值；记录 d 分布直方图；必要时退化为绝对阈值 B/m（类无关） |
| BW-EDF 在轻载区过度节制 | 轻流恒不阻塞 + 老化豁免 + C 自适应 ⌊B/d_heavy⌋；A3 不回退判据兜底 |
| 组合候选与 π 动作重复浪费预算 | 去重（key 相同跳过）；组合候选排最前 |
| 3840 深队列 mpc-v2 单 run 过长 | 预算口径不动；冒烟超 40min 先降 Q 网格/候选窗（记录口径） |
| 与 E25 旧结论的可比性 | (edf,F) 旧口径保留 + code_rev 分版本 |

## 9. 分期

- **一期（本设计）**：M1 组合器 + M2 BW-EDF 延续/兜底 + M3 观测 + 全量 A/B/C；
- **二期（视一期数据）**：真 H>1 多步规划（治残余信用分配）、在线分位数配额、门控容忍（n_tie 数据驱动）。
