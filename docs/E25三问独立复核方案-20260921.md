# E25 三问独立复核方案

创建日：2026-09-21。对象为《测试报告-E25实施-20260919.md》。本次从代码、原始/派生 trace 和新重放建立证据，不以已有同题分析作为事实来源。

## 问题与核查方法

1. 区分计算公式的实现正确性、模型语义、真实 NPU 标定。独立推导 attention 配对数、纯计算时间与含读服务时间；核对规格和单测。外部依据采用 GQA 论文原文（https://arxiv.org/abs/2305.13245），不能由 KV 头数推断隐藏维度或真实算力。
2. 区分实际带宽、申请带宽和跨流争用。沿 `StorageSim.allocate/advance` 与 `aggregate_run` 核查图 H。用只读运行期记录计算 `Σmin(q_i,B)>B` 的时间比例，并与 `Σq_i>B` 对照；前者直接识别共享与独立分配的差异。
3. 用完整 32 层读取量建立字节守恒预算，再选择已有 E25 配置重放。固定到达时间、SLO、计算画像和批能力；降低 B 不重算 λ0。分别回答能否出现间歇争用、能否保证 MPC 收益，禁止互相替代。

## 重放与验收

- 属于 E25 既有格点的独立诊断，不新增调度机制、不改物理内核或 CLI 实验种类。诊断工具放 `tools/`，原始输出落 `results/`。
- 冒烟：ToolAgent、窗口 9、OL、ρ=0.6、m=4、B=20/15，检查实际速率不超 B、字节守恒和跨流争用非零。
- 冒烟通过后：三 trace 的 B=80/20、ToolAgent B=15、Conversation B=10/ρ=0.9、Synthetic B=15；窗口 {0,4,9,14,19}，全窗口 FCFS 重放，报告窗口中位数及范围。补充 ToolAgent m=8、ρ=0.3、B=20（到达时间与 m4/ρ0.6 一致）以识别计算扩容作用。
- 间歇争用判据：并非持续供不应求（到达期平均所需字节率低于 B），同时观察到多流竞争与非竞争时段；至少列竞争占时、STALL、计算占时、实际吞吐时序，不能仅凭一个桶均利用率阈值判定。
- 独立观察器不向策略暴露状态，不改事件与流分配；小世界上对照原生运行逐请求完成时刻和字节账本。
- 不重跑昂贵的全 MPC 矩阵，不由 FCFS 资源诊断宣称 MPC/local 有显著收益。既有收益只能回到原始记录、同窗口同目标配对核算，并明确属于历史结果。
- 新结果文档置于仓库根并嵌入新命名图，不覆盖正式图。提交前全量 pytest；每个完成逻辑单元提交推送，只暂存本次文件。
