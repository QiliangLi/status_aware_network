## 1. 问题定义

E26 系列已有数据点（全部 A:B=1:2——该比例下 A 带宽需求 92<120 GB/s，A 不过剩，调度空间被物理上限封顶，见 E26d §3.3 守恒论证）：

| 数据点 | 到达形态 | FCFS | mpc_v2.1 | 差距 |
|---|---|---|---|---|
| E26c D1（交错泊松） | A 完全打散 | 78.3% | 90.4% | +12.1pp |
| E26d D3（全块突发） | 32A+64B 连续块 | 66.7%（=EDF） | 76.0% | +9.3pp |

本实验补上两个缺失维度：**①A:B=1:1**（A 需求 138>120，供给过剩——从"谁都活得起"变为"比拼谁死得少"，调度价值最大化区）；**②A 集中度两档**（k=4 轻度集中 vs k=16 高度集中，簇大小=单次涌入队列的 A 条数）。

## 2. 负载设计：D1c（A 簇泊松）

### 2.1 生成规则

两条独立的随机流（seed 驱动，CRN：同格点全臂同一份流）：

- **A 簇流**：簇心间隔 ~ Exp(均值 k/λ_A) 独立同分布；每个簇心时刻**恰 k 条 A 同刻到达**（rid 连续）；120 条 A 取整后余数入末簇（k=16：7 簇×16+末簇 8）。
- **B 泊松流**：间隔 ~ Exp(均值 1/λ_B) 独立同分布，**每次到达 1 条**（与 E26c D1 背景一致——控制变量，唯一被扫描的是 A 集中度）。

| 参数 | 值 |
|---|---|
| A:B | 1:1（120A+120B） |
| k | {4, 16}（4：30 簇、簇心间隔均值 41ms；16：7+8 簇、间隔均值 163ms） |
| λ | 196 req/s（r1.1，供不应求、队列持续加深）；λ_A=λ_B=98/s |
| α / 规模 | 4 / 240 条（到达期 ≈1.22s）；T0 由引擎解析式生成，deadline=arrival+4×T0 |

**k ≠ 并发 A 数**：k 是"单次**到达**的 A 条数"；FCFS 实际同时在跑的 A 数由"到达批量 × 在途重叠"决定——k=4 时稳态并发 A ≈16~17 条（Little 定律：λ_A×单条时长的重叠与簇大小无关，越生死线 n≈12）；k=16 时簇占队首、叠加尖峰 16~22。MPC 与 k 无关恒 cap≈4。

### 2.2 预计算预测（α=4 → A 期限 198ms；单条 A 存活需 ≥8.0 GB/s）

| 场景 | 并发构成 | 每 A 分得 | 单条 A | 预测 |
|---|---|---|---|---|
| FCFS（k=4） | 稳态 ~16A+16B | 6.2 GB/s | 257ms | ✗ 越线，A 成批死 |
| FCFS（k=16） | 稳态+簇尖峰 16~22 | 更差 | ≫257ms | ✗ 比 k=4 更惨 |
| EDF / local（两 k） | A 堆队首 25~32 并发 | ≤4.8 | ≫375ms | ✗ A 全灭（与到达序无关） |
| **MPC cap4（两 k）** | 4A+28B | 20.6 GB/s | 77ms | ✓ 活；A 吞吐上限 ~64/s < 到达 98/s → 尾部 A 仍死（物理），比拼谁死得少 |

### 2.3 预注册假设（跑前写死）

- **H1**：两档 MPC−FCFS ≥ +15pp；k=16 相对 k=4 FCFS 单调恶化。
- **H2**：EDF/local 全档垫底（A 全灭，B 也被挤）。
- **H3**：MPC（S/T 同）全档第一；簇冲击响应显示每簇派发并发 ≤5。
- **H4**：θ=S≈θ=T。
- 备用旋钮（H1 不达时先冒烟再入矩阵）：比例 2:1 或 α=2（期限 99ms → 生死线 16 GB/s）。

## 3. 策略（5 臂）

`fcfs` / `edf` / `localS_v2.1` / `mpcS_v2.1` / `mpcT_v2.1`；引擎口径与 E26d 完全一致（base=bw_edf, composer=True，事件预算 2 万/决策，budget_s=3600，H=1）。

## 4. 实验矩阵与成本

| 矩阵 | 1:1 × k∈{4,16} × 5 臂 × 1 seed | **10 runs**（MPC 类 6 个） |
|---|---|---|

**seed 说明**：D1c 是随机负载，每 seed=一份到达流抽样（同格点 5 臂共用=CRN）。默认 1 seed（预期效应 ≥15pp vs 单 seed 噪声 ±3~5pp）；**条件补测规则：若任一格点 MPC−FCFS <10pp（进入噪声带，k=16 的 8 簇抽样方差是主要风险），该格点补 2 个 seed 取中位数再下结论**。

成本：MPC 类单 run 实测 local≈7 / mpcT≈10 / mpcS≈13 分钟 → 6 个 ≈1h CPU ÷ 2 并行（每 k 一路）≈ **~30 分钟墙钟**（fcfs/edf 秒级忽略）。

## 6. 验收标准

1. H1 成立；不成立 → §2.3 备用旋钮流程并如实记录。
2. MPC 全档 ≥ 其余四臂；违反 → 健康审计+候选窗检查（E26b §9 口径）。
3. 生成器退化对拍（k=1 ≡ e26.d1_specs 同 seed 逐位一致）在单测层完成。
4. 簇冲击响应：MPC ≤5/簇；FCFS ≈ k。
5. 全量 pytest 绿；`tools/cq_mpc_health.py` 无 DEGRADED。

### 8.2 D1c 生成器伪码（含 RNG 与余簇规则）

```python
def d1c_specs(k, seed, alpha=4, n_A=120, n_B=120, lam=196.0):
    rng = np.random.Generator(np.random.PCG64(seed))
    lam_A = lam / 2                      # 1:1 → λ_A=λ_B=98/s
    t, a_cls = 0.0, []
    while len(a_cls) < n_A:              # A 簇流：间隔 Exp(k/λ_A)
        t += rng.exponential(k / lam_A)
        a_cls += [(t, "A")] * min(k, n_A - len(a_cls))   # 末簇补余（k=16: 7×16+8）
    b_arr, t = [], 0.0
    while len(b_arr) < n_B:              # B 流：间隔 Exp(1/λ_B)，每次 1 条
        t += rng.exponential(1 / lam_A)
        b_arr.append(t)
    # 合并（按时刻；同时刻 A 簇 rid 连续）→ RequestSpec(rid,arrival,h,u,class,T0,deadline)
    T0 = make_T0(specs, E26_PROFILE, F(120), F(200))     # e26_ab 已有
    deadline = arrival + alpha * T0                      # α=4
```

seed 约定：`seed = 格点基号*8 + rep`（沿用 e26.d1_seed；k=4→基号 0、k=16→基号 1）。CRN：同格点 5 臂共用同一份 specs。

## 9. 局限

- 簇内同刻是简化（真实簇有毫秒抖动）；与 E26d 同刻口径一致。
- 1:1 下 A 供给过剩（98/s 到达 vs ~64/s 上限）→ 尾部 A 必死属物理，SLO 绝对值整体下移，看相对差距。
- k 只取两档（4/16）——若两档间出现非单调迹象再补点；k=16 每 run 仅 8 簇，单 seed 抽样方差由条件补测规则兜底。
- 单 λ（r1.1）单 α（4）；240 规模。
