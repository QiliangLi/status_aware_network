# 共享 KV 存储感知推理调度 · 仿真 v2：架构与实验设计

> 依据 `discussions/共享KV存储感知推理调度-16x9.png` 架构图对仿真器做的 v2 升级，
> 以及围绕图右侧五个"需要联合考虑的问题"设计的实验 E5–E9。
> 对比基线映射见《[五工作的Scheduler-Engine修改与主流默认实现-20260904.md](五工作的Scheduler-Engine修改与主流默认实现-20260904.md)》。
> v1（单/多 backend、E1–E4）保持不动，见《KV存储压力感知调度仿真设计-20260901.md》。

## 1. 架构图 → 仿真模块映射

| 架构图组件 | 仿真实现 | 说明 |
|---|---|---|
| 全局推理调度器 | `policies2.*.decide(req)` | 每请求一次性联合决定 worker × 副本 × 动作 × F |
| 计算节点 1/2/3 + 小型本地显存缓存 | `GpuPool` + `LocalKVCache`（LRU，容量 GB） | 完成请求后前缀 KV 写入本地缓存；命中则零存储流量 |
| 高速网络 | `SharedKVStorage("fabric")` + 每路径静态延迟 `path_lat` | 所有取回/复制流量共享 fabric 带宽（processor sharing） |
| 存储节点（内存+固态盘） | 每节点两个 `SharedKVStorage`（mem/ssd tier） | 双层带宽独立、背景负载独立（动态压力来源） |
| 元数据目录 | `MetadataDirectory` | class → {(node, tier)} 副本集合 + 节点占用/容量压力 |
| KV 副本（一或多份） | `TopoConfig.replicas` 初始放置 + 运行时复制 | 任何 worker 可达任何副本（路径延迟不同） |
| 存储状态反馈（红虚线） | `StorageObservable`（陈旧/EMA/带噪）×7 资源 | 计算侧唯一合法信息源；Oracle 例外 |
| 访问成本查询接口 | `quote.AccessCostQuery` | 输入 bytes+worker+node+tier → 预计完成时间/压力等级/置信度 |
| 存储侧状态（排队时间/可用带宽/路径拥塞/热点/容量压力/副本可用性） | 观测视图 + `pressure()`（NORMAL/WARM/HOT/CRITICAL 滞回）+ `capacity_pressure()` | 压力等级供 Q4 控制器使用 |

关键语义：

- **fetch 链路** = 路径延迟 → tier 服务 → fabric 传输（三级顺序流体）；
- **partial（部分重算）**：取回 F∈{25%,50%,75%,100%} 前缀 KV，同时 GPU 重算剩余 (1−F) 前缀+suffix，
  overlap 模式完成时间 = max(取回链, GPU 队列+计算)（CacheFlow 式 I/O/计算重叠）；
- **recompute**：GPU 全量重算；**local**：worker 本地缓存命中，仅做 suffix prefill；
- 复制/迁移流量本身在源/目的 tier 上排队（占用带宽，与前台取回竞争）。

## 2. 图右侧问题 → 实验 E5–E9

| 问题 | 实验 | 场景要点 | 对比策略（映射） |
|---|---|---|---|
| **Q1 请求在哪个计算节点执行？** | **E5** | w0/w1 GPU 忙且持有热点类 A 本地缓存，w2/w3 空闲（locality↔load 冲突） | rr2 / load2（无 KV 感知）；default2（Dynamo credit + vLLM 命中即取）；tensorcast2（locality+load 联合）；**joint2（本方向）**；oracle2 |
| **Q2 从哪个 KV 副本、哪条路径读取？** | **E6** | A 三副本：n0.mem 方波高压、n1.ssd 稳定但层慢、n2.mem 反相方波 | nearest2（mem 优先+最近路径，Dynamo credit 式）；rrrep2（盲轮询）；static2（AAFLOW+ 静态成本选副本）；**joint2**；oracle2 |
| **Q3 拉取、部分重算还是完整重算？** | **E7** | 全部类副本集中单节点且背景逼近饱和；所有策略共享动作空间，只差信息源 | alwaysfetch2（主流默认）；static2（AAFLOW+ 二选一）；partial_static2（CacheFlow 静态 F+重叠）；**joint2（动态 F）**；joint2_seq（无重叠消融）；oracle2 |
| **Q4 何时预取、迁移或复制？** | **E8** | A 热点仅 (n0,mem) 一份且背景高，n1/n2 空闲；引擎统一 joint2，只比存储侧控制 | none（只能靠重算逃逸）；reactive（持续 HOT≥2s 才复制）；predictive（低阈值+短保持，提前触发）；full（初始全副本=上界） |
| **Q5 如何避免热点、争抢和局部最优？** | **E9** | A 双副本反相方波背景 + 状态反馈刻意陈旧（200ms、σ=0.1），制造羊群条件 | joint2（逐请求贪心 = 局部最优）；**coord2（滞回粘住+次优副本概率分流 = 协同）**；oracle2（全局上界）；观测队列振荡/副本切换率/goodput regret |

预取（Q4 的一部分）在 v2 中以"完成即写本地缓存"的被动形式存在，主动预取留作后续工作；E8 聚焦复制/迁移。

## 3. 策略 → 相关工作映射（对照文档 §4/§5）

| 策略 | 对应工作/默认 | 决策信息 | 动作空间 |
|---|---|---|---|
| alwaysfetch2 | vLLM/SGLang 默认（D3/D4 命中即取） | KV 存在性 | local/fetch/prefill |
| default2 | Dynamo KV-credit router + vLLM | KV 位置（tiered credit）+ GPU 负载 | local/fetch/prefill |
| tensorcast2 | TensorCast | locality + GPU 负载联合（静态传输成本） | local/fetch/prefill |
| nearest2 | Dynamo credit 式副本选择 | tier 优先 + 路径延迟（静态） | local/fetch/prefill |
| static2 | AAFLOW+ | nominal 带宽成本 | local/fetch/recompute/prefill |
| partial_static2 | CacheFlow | nominal 带宽 + F 网格 + 重叠 | + partial |
| **joint2** | **本方向** | **访问成本查询（实时压力）+ F 网格 + 重叠** | 全部 |
| **coord2** | **本方向+协同** | joint2 + 滞回/抖动（抗羊群） | 全部 |
| oracle2 | 上界 | ground truth hypothetical 精确预测 | 全部 |

## 4. 复现

```bash
.venv/bin/python -m pytest tests/ -q            # 含 v2 不变量测试
.venv/bin/python -m sim.run --exp v2 --seeds 8  # E5–E9 全量
.venv/bin/python -m sim.run --exp e5 --seeds 2 --duration 120   # 单实验冒烟
```

输出：`results/e5..e9/summary.csv` 与 `docs/figures/fig_e5..e9_*.png`。
