数据:Mooncake 三文件(首现命中)+ AgentX 样本 2 会话(理想前缀命中)。画像:默认 ProfileConfig,L=32 层。复算:tools/tfs_trace_gain.py / tools/tfs_gain_html.py。

结论一:原始节奏下大门不开(B*≤5.1 GB/s ≪ 供给 80~120) 结论二:结构前提齐备(簇内请求 87.5~99.8%,d 的 CV 1.9~5.0) 结论三:比重由部署决定——收紧 B 或加压回放即开门

一、拖动带宽 B:每条 trace 有多少落在收益区

纵轴:超订窗口(或涉及请求)占比,净口径 = 1 秒内到达读取量 > B 且窗口内 ≥2 条请求。横轴:B,对数刻度。灰色竖线:E23 用 B=80、E26 用 B=120。曲线左端起点 ≈ 该 trace 的窗口峰速率——B 低于它才出现收益区。

四、收益场景四条件与换 case 三检查

条件怎么判断缺了会怎样
① 分诊区(大门)ρ = B*/B ≥ 0.7,或窗口读取速率 > B收益为 0,但无害
② 簇到达50ms~1s 内多条重流无错峰对象
③ 轻重异构d 分布分散;存在零读或轻流分诊无信息
④ 期限有松紧部署参数 α退化为到达序
  1. 看 d 分布:CV < 0.5 时收益上限约 0。
  2. 算 ρ:ρ < 0.7 时大门不开。
  3. 看簇与期限:有簇、期限有松紧,结构齐备。随后与 fcfs 对跑一次(TFS 单次运行秒级)。

五、口径注意

首现命中(Mooncake)与理想前缀命中(AgentX)口径不同,数字不可互推。窗口超订是到达侧上界,不建模排队动态。AgentX 样本仅 2 会话,需全量 393 会话并发回放才能下结论。“ρ≥0.7 时 TFS 捕获九成收益”来自 E26f 合成工况(95%/91%),trace 回放未验证。
